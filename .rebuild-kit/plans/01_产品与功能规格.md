# 产品、教学流程与功能处置规格

本文件是新产品设计，赛题依据见[F1]，旧功能依据见[F2/K*/C*]。不要求完整复制两个旧产品。

## 1. 四种用户路径

### 1.1 新学习者

团队演示账户或被授权的试用账户登录 → 选择实际年级/教学阶段与偏好 → 查看“你可以从这里开始” → 打开一节已发布课程 → 系统说明本课目标并主动给出第一项活动。新手无历史时明确“还没有足够学习记录”，不用假画像填首页。

年级与学段是不同字段语义：grade=1..12或尚未提供；stage四档来自年级或学生明确选择；同时给出时必须一致。只选学段时不能暗自把学生当成该档某一个年级。切换阶段会刷新策略与候选课程，不抹除历史记录；进行中的章节以原快照保留，切换需新建策略版本并告知，不静默改题。

### 1.2 一节完整课

创建/恢复lesson session → 目标与先备检查 → 当前知识点讲解 → 必要时操作动画/打开资源 → 回答理解检查 → 正式小测或代码实践 → 根据实际结果补充解释 → 学生确认完成学习活动 → 生成基于证据的下一步。

用户可随时问别的问题、暂停、跳过非必需活动或结束。偏题对话不自动前进教学phase。重新进入章节应恢复已保存状态；不是重新“欢迎来到本章”并再次创建测验。

### 1.3 遇到不会/答错

首次错误：解释错误涉及的概念，给一个更小的提示；重复错误：换具体例子或媒介；学生请求：可显示答案解析，但记录提示与最终作答状态。不要用羞辱、排名压力或惩罚性连击。

推荐变化由真实答案、提示使用、完成状态或明确偏好驱动。看过资料不等于理解，耗时长不等于能力弱，模型文风判断不作为人格/智力画像。

### 1.4 管理者制作教学内容

导入旧课程形成待审核草稿 → 对照原文与许可核对 → 配置知识点、资源、练习、CodeLab关联 → 可调用Designer产出草稿 → 预览并自动验证 → 人工审核 → 创建不可变发布版本 → 打包供Knodo读取 → 核对部署版本 → 学生使用。

不得让AI自行签“人工审核通过”，不得用改状态的方法伪造审核。已有源码声称原创或CC许可仍需保留来源记录，不能据此替第三方素材确认版权。

## 2. 旧功能的明确处置

| 旧功能 | 决策 | 新落点/验收 |
|---|---|---|
| 账号登录、档案、偏好、头像 | 保留需求、重建接口 | 身份/设置；头像可后于核心登录，真实上传权限与大小限制 |
| 学段选择 | 重建 | 四档；非法年级422；1–2年级内容缺口必须补 |
| 书库、章节、静态图解 | 选择性迁移 | 版本化课程和阅读器；归档全部旧资产但不自动全发布 |
| 章节选中文字解释/总结 | 保留 | 本地核对chapter/block归属和版本；选择文本是非可信补充而非指令 |
| 桌宠、拖拽、换装 | 保留为可选呈现 | 教师面板不依赖宠物；复用图像需许可；不计教学动画 |
| 教师人格切换 | 收敛 | 两种展示语气可保留，不能覆盖四学段策略或安全规则 |
| 聊天历史/长对话 | 重建 | 本地会话权威记录+远端绑定；从开始就有历史页面，不只保留最新会话 |
| 出题、判分、提示、错题 | 保留规则、重建流程 | 题目快照与答案隔离；真实难度/题量策略 |
| 阅读进度/显式完成/时长 | 保留并加固 | 完成活动与掌握证据分开；不把滚到底算掌握 |
| 记忆、证据质疑、编辑/遗忘 | 保留差异化 | 简化为证据投影+候选确认；不复制五层聚合的全部工程复杂度 |
| Episodes/agent.md导出 | 合并展示/后置格式导出 | 成长时间线保留；Markdown只是输出格式，不再建另一套记忆系统 |
| 推荐/唯一下一步 | 重建 | 统一教学状态；GET只读；按已知证据给理由 |
| 自建Embedding/RAG与旧向量 | 不迁移运行实现 | 课程上下文和Knodo版本化知识；平台能力不足需ADR，不偷偷恢复自研堆栈 |
| PG任务队列 | 保留机制、重建任务域 | 新库新队列，幂等、租约、重试、死信、心跳 |
| 语音ASR/TTS | 适配接口与偏好保留 | 完整真实验证前标不可用；与文字独立，不能假装Knodo已有语音API |
| CodeLab与评分 | 精选迁移并重验 | 新runner构建、身份/超时/输出限额；课程和学习事件关联 |
| 后台管理 | 重建 | 草稿、来源、发布、资源、Bot绑定版本、任务状态和审核日志 |
| MinIO/Redis等声明 | 不为数量而保留 | 未启用就不部署；多实例前补实际验收 |
| 旧迁移、旧数据库、未审题、缓存 | 不复制 | 新数据库从0迁移；DRAFT保留原审核含义 |

## 3. 信息架构和页面

五个主要入口：`学习`、`课程`、`练习`、`成长`、`设置`；管理端单独。CodeLab可从课程活动和练习入口进入，不需要额外同级大导航。

| 新页面（拟定） | 必须可操作 | 必须存在的状态 |
|---|---|---|
| `/login` `/onboarding` | 登录、选择学段/偏好 | 未配置试用、无权限、错误、会话过期 |
| `/learn` | 继续本课、下一步理由 | 无历史不生成假统计；部分依赖不可用 |
| `/courses` `/courses/:id` | 学段筛选、搜索、章节选择 | 无该学段课程、内容未发布、不适用解释 |
| `/lessons/:sessionId` | 内容、教师、练习/资源/动画/代码 | 载入、生成中、取消、平台失败、旧回复失效、恢复 |
| `/practice` `/quizzes/:id` | 多题、提示、复盘 | 无题、答题幂等、提交超时、答案未解锁 |
| `/code/:taskId` | 编辑、运行、错误、测试、反馈 | 无Docker、超时、系统错与学生错区分 |
| `/history` `/conversations/:id` | 分页历史、继续/归档 | 已删除、不属于当前学生 |
| `/growth` `/growth/memories` | 证据、趋势描述、质疑/确认/遗忘 | 证据不足、后台更新中、不推测不存在记录 |
| `/settings` | 档案、偏好、语音、登出 | 保存冲突、隐私请求进度 |
| `/admin/*` | 课程/资源/审核/平台版本/任务 | 角色不足、草稿未就绪、同步失败 |

## 4. 学习工作台交互规格

桌面：左侧可收起章节导航，中间学习画布，右侧教师栏。进入代码活动后中间切换为编辑器与运行结果，教师仍知道当前任务；进入动画后展示真实控制按钮。不要同时显示所有统计、书单、宠物、反馈表单和活动卡。

移动端：学习画布为主，教师与活动通过明确标签/抽屉切换，当前目标始终可找到；不把三列缩成三条极窄列。键盘弹出时输入框不被底栏遮挡，代码区可横向滚动但整页不溢出。

低龄模式：更少同时出现的动作，较大字号/点击区，短句与图示；不能只有配色改变。高龄模式：术语、步骤、代码和依据更充分，但由已有基础决定深度。UI结构源于教学需求，不要求四套完全独立前端。

T07先生成页面结构与组件状态规格（有可用设计工具可先做概念图）；这不是只设计营销首页。随后用真实API数据接通、浏览器截图逐项验收。主内容和控制必须是真组件，不把效果图当页面。

## 5. 教学策略v1（明确是待校准设计）

| stage | 内容边界 | 初始实践偏好 | 题量建议 | 注意 |
|---|---|---|---|---|
| PRIMARY_LOWER | 生活观察、分类、顺序、AI的局限 | 看图/排序/口头解释 | 1–2 | 不默认要求键盘写Python，不以术语背诵代替理解 |
| PRIMARY_UPPER | 步骤、简单规则、数据例子 | 拖动/匹配/基础代码可选 | 2–3 | 不承诺完整Scratch编辑器，未实现就别出现“启动Scratch” |
| JUNIOR | 变量/条件/循环、查找、AI与数据关系 | 代码+可视化实验 | 2–3 | 错误时降到具体例子，不固定MEDIUM |
| SENIOR | 算法边界、训练/验证、偏差与评价 | 项目式代码、比较与解释 | 2–3 | 避免把生成模型讲成必然正确 |

策略输入：stage、可空grade、当前课程先备知识、用户偏好、最近同知识点作答/提示记录、可用能力。输出：难度范围、题量上限、讲解风格、候选资源、候选代码任务、允许动作。具体数字必须存在可修改配置和单测，不能宣称已由学习科学验证。

没有知识证据时用初始策略；一次错误不永久贴标签；连续/跨时点证据才增强判断。学生可纠正偏好。不可用的媒介不推荐；系统给出替代文字解释，不伪造动画或声音。

## 6. 状态机与主动引导

phase：`ORIENT → EXPLAIN → CHECK → PRACTICE → REFLECT → COMPLETED`。
生命周期status：`ACTIVE/PAUSED/ENDED`；运行status另行定义，不把“模型正在生成”混成教学phase。

进入已发布章节时创建/恢复session并发出`LESSON_ENTERED`事件；后端依session及事件幂等键决定是否需要新引导。此操作有写入和付费可能，使用POST，不在GET页面数据时暗中调用模型。

只有后端转换表能更新phase：Tutor可建议EXPLAIN/CHECK/PRACTICE/REFLECT，不能直接建议或写COMPLETED。进入练习前创建真实测验/任务实例；收到真实结果才允许进入相应复盘。学生显式结束和完成活动不是同一状态；不会因刷新/失焦/关闭标签就“学会了”。

每次run携带`lesson_session_id/base_revision/curriculum_revision`；用户切章节/改策略/取消后，迟到响应标记STALE并只存日志，不显示在新课、不执行动作。遇偏题保留返回锚点；“继续”恢复已存phase而不是猜历史。

## 7. 何时自动执行、何时需要确认

| 输出/行为 | 决策主体 | 用户体验 |
|---|---|---|
| 解释、引用、理解检查 | 后端校验后显示 | 不每句话弹确认 |
| 推荐已发布资源/动画 | 后端目录与适龄校验 | 展示可点击卡，不自动打开任意URL |
| 创建小测 | 学生点击/开启引导模式后，后端幂等创建 | 不因模型一句话重复建三场测验 |
| 运行代码 | 学生明确点击运行 | Agent不能自主执行学生代码 |
| 正误/得分/完成 | 业务服务确定 | 模型不能覆盖 |
| 偏好/长期记忆AI建议 | 候选+学生确认或质疑 | 可拒绝、编辑、遗忘 |
| 发布资源/题库 | 管理员审核与版本提交 | 不让模型自签通过 |
| 删除账号/大批内容 | 专门授权流程 | 不从聊天直接执行 |

## 8. 可展示创新而不夸大

建议围绕三件事展示：相同概念跨学段的教学活动变化；基于真实错误的“讲—练—复盘—下一步”；学生能看到和纠正教师依据的学习观察。将Knodo作为可配置执行底座，而不是把“用了某平台”本身写成创新成果。需要对照实验或样例支撑，不预测获奖或评分。
