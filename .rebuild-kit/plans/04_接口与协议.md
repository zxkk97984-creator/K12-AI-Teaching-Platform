# 新项目接口与协议规格

这份文件规定**霜铃自己的接口与业务语义**，不声称这些路径属于Knodo。T03完成字段级契约评审；实现后后端Pydantic/OpenAPI成为HTTP接口主源，前端类型由其生成。本包JSON Schema是AI边界的初始规范，修改须记录版本和同步样例/校验器/提示词。

## 1. 三层契约，不混写

| 层 | 主人 | 责任 |
|---|---|---|
| 浏览器↔霜铃API | 本项目OpenAPI | 鉴权、学生操作、资源与学习结果 |
| 霜铃↔Agent业务语义 | 本包`contracts/` | 本轮真实上下文、允许动作、教学回复与草稿 |
| 霜铃↔Knodo HTTP/SSE | 已登录的官方文档与实测样本 | 认证、请求字段、会话、结束/错误/用量；未知项不得补猜 |

`request_id`由客户端为一个意图生成并稳定重试，后端校验格式与归属；它不是Knodo提供幂等的证明。数据库唯一键至少包含actor/operation/key；同键不同有效载荷返回409，不能重放错内容。未经校验的模型字段不能成为actor、权限、审核状态或真实工具结果。

## 2. 建议本地HTTP目录

公共前缀`/api/v1`。路径是新设计，T03可以在保留语义的前提下统一命名一次，之后不得每个任务另起名字。

| 路径 | 方法 | 语义/关键边界 |
|---|---|---|
| `/auth/login`, `/auth/logout`, `/me` | POST,POST,GET | 同源HttpOnly会话；登出服务端失效；所有写操作CSRF/Origin校验 |
| `/me/profile`, `/me/preferences` | PATCH | 年级/学段/兴趣/主动引导/语音偏好；profile_revision递增 |
| `/courses`, `/courses/{id}`, `/chapters/{id}` | GET | 仅已发布且适用范围内版本；正文不含答案库/隐藏测试 |
| `/lesson-sessions` | POST | 绑定学生、章节发布版本和策略；幂等建立，返回初始状态 |
| `/lesson-sessions/{id}` | GET | 恢复状态；读取不创建新消息/新测验/推荐记录 |
| `/lesson-sessions/{id}/events` | POST | ENTER/RESUME/PAUSE/ASK/REQUEST_PRACTICE等允许事件；行为合法性校验 |
| `/lesson-sessions/{id}/turns` | POST | 建立教学run，通常202；一个有效意图只触发一次模型执行 |
| `/agent-runs/{id}` | GET | 本地run状态、已校验回复和可恢复结果；不含远端密钥/内部日志 |
| `/agent-runs/{id}/events` | GET | 自有SSE；重连读取已存在run，绝不重新调用模型 |
| `/agent-runs/{id}/cancel` | POST | 请求取消本地生成；远端是否成功取消另记，不能断网即宣称不收费 |
| `/conversations`, `/conversations/{id}/messages` | GET | 本地展示历史；严格所有权，分页；按绑定版本管理远端上下文 |
| `/action-candidates/{id}/decision` | POST | accept/reject；仅有业务副作用且需学生选择的动作走确认 |
| `/quiz-sessions` | POST | 由合法候选/明确点击创建；固定题目快照与来源 |
| `/quiz-sessions/{id}` | GET | 只返回该学生有权看的题干/反馈；作答前不返回答案 |
| `/quiz-sessions/{id}/questions/{qid}/answers` | POST | 判分、attempt、提示影响、真实事件、幂等 |
| `/quiz-sessions/{id}/questions/{qid}/hints` | POST | 分层提示；受阶段/次数/版本限制 |
| `/me/progress`, `/me/learning-next`, `/me/recommendations` | GET | 读不写；返回理由、证据、计算版本；无数字掌握度伪精确 |
| `/me/memories`, `/me/evidence/{id}` | GET | 只本人可看；来源记录与有效状态可回查 |
| `/me/memories/{id}` | PATCH | CONFIRM/DISPUTE/EDIT/FORGET；撤回内容不继续注入 |
| `/me/data-export`, `/me/deletion-requests` | POST | 私有导出/删除请求状态，不把软删宣称外部已物理删除 |
| `/resources/{id}`, `/resources/{id}/content` | GET | 学段/发布/课程权限，安全下载与真实预览；无任意URL代理 |
| `/code-tasks`, `/code-tasks/{id}` | GET | 预置框架；隐藏测试与参考解不返回 |
| `/code-runs`, `/code-runs/{id}` | POST,GET | 固定代码快照/哈希；异步任务；运行结果来自runner |
| `/code-runs/{id}/feedback` | POST | 用该run结果生成辅导，AI不可修改可信判定 |
| `/admin/curriculum/*`, `/admin/resources/*` | GET/POST/PATCH | 内容草稿、审校、发布、版本/授权与审核人 |
| `/admin/generation-jobs` | POST/GET | Designer教研任务、真实产物、失败状态与重试预算 |
| `/admin/platform-status` | GET | 安全配置状态、已有验证时间，不自动调用收费模型 |
| `/health/live`, `/health/ready` | GET | 活着 vs DB/worker/存储可用；按启用能力列状态 |

不要实现一堆不可用空接口。按任务纵向实现；未启用功能不显示正常按钮，不返回伪造数据。账号注册可以先采用团队创建的合成演示账户；真实学生开放策略未确认前不开放公网自助注册。

## 3. 教学请求/回复

请求Schema见`teaching-request.schema.json`。可信学生身份在后端解析，线上不从请求中的昵称认定身份。对平台使用不直接暴露本地user_id的会话引用，仍按个人数据处理范围管理，不宣称已匿名。

请求内容：事件、当前phase/revision、课程/策略版本、适用学段、已授权正文片段、少量学习证据、允许动作和资源/任务候选。没有可用正文时不能让Tutor装作“据教材”；返回明确缺资料或仅一般解释，不能伪造引用。

回复Schema见`teaching-response.schema.json`。学生可见正文与动作分开。第一版每回合最多一个教学动作，降低解析与状态复杂度。引用只允许本轮给出的source_id/revision；这只能验证“引用存在且有权使用”，不能自动证明文字确实支持结论，评测仍须核对语义。

`phase_suggestion`是建议，不允许模型直接结束课程；COMPLETED只能由本地合法事件、活动结果和学生确认产生。旧revision、课程已改、会话已结束、题目已过期的结果标为STALE，不能覆盖新状态。

## 4. 候选执行规则

| 类型 | 默认策略 | 校验与落库 |
|---|---|---|
| 普通讲解、检查理解问题 | 输出校验后直接展示 | 不需每句弹确认；不自动算完成事实 |
| OFFER_QUIZ | 学生明确练习请求可授权本次创建，否则按钮确认 | objective/count/difficulty在本轮允许范围，固定题目快照 |
| OPEN_RESOURCE / OPEN_ANIMATION | 显示资源卡，学生打开 | ID在候选清单、已发布、适龄；前端不执行模型给的URL |
| OPEN_CODE_TASK | 显示实践卡，明确点击后进入 | task与课程/知识点关联，runner可用性如实显示 |
| 学习计划大幅调整/长期偏好记忆 | 另外的候选流程并经用户确认 | 不因一次答错改整个长期方向 |
| 成绩、章节完成、审核通过、账户权限 | **不允许模型直接写** | 来自相应可信服务及真实操作 |

候选accept必须重新核对student/lesson/base_revision/课程版本/状态/过期时间，不只相信创建时已经校验。重复同决定幂等；冲突决定返回409。创建测验、候选状态、课程状态、关键事件在同一短事务内写入。

## 5. 题目草稿与答案保护

Designer只收到课程、学段、题型、难度、数量、来源与错误概念摘要，不接收整个学生私聊。返回`quiz-draft.schema.json`规定的题干、选项/答案、解析、三级提示、来源。答题会话由本地另建，不能采用模型自造的数据库ID。

首版支持SINGLE_CHOICE、TRUE_FALSE、ORDERING，后续可补MULTIPLE_CHOICE/FILL_BLANK。不得为了“支持更多题型”用不可靠的字符串判等代替明确语义。排序活动支持鼠标/触屏和键盘升降按钮，不能只有拖拽。

区分三种状态：`DRAFT`（仅格式草稿）、`AUTO_VALIDATED`（结构和可自动判断项通过）、`HUMAN_APPROVED`（真实人员审校）。私人随堂练习可在明确AI生成标签下使用经过限定校验的草稿；公共复用题库只使用人工审校版本。自动检查不应伪造人工审核人/时间。赛前示范章节优先使用真实审校题，现场生成的质量单独展示与统计。

答案和参考解不是学生DTO的一部分；提示与解析按学习阶段逐步展示。不能在Teacher会话里先发完整答案再寄望Prompt“不泄漏”。Designer会话与Tutor会话必须物理上分开绑定，题稿schema不允许被SSE整体转发给学生。

## 6. 正确流式、进度与完成

R1默认完整结构化返回。后端可以即时发送“请求已接收/正在生成”等真实阶段，但不得伪造工具调用或虚构百分比。

```text
event: run.started  data: {run_id, lesson_session_id, base_revision}
event: run.progress data: {run_id, phase:"WAITING_PROVIDER"}
event: message.ready data: {message_id, text, source_refs}
event: action.ready data: {candidate_id, type, display_payload}
event: run.done data: {run_id, status:"SUCCEEDED", persisted:true}
```

这些是本地事件，不是Knodo官方事件。结构化正文在所有必要校验后才能发message.ready；持久化成功才发run.done。失败发run.error，实际状态和重试权限需可查询。纯文本native streaming作为O04，需验证平台协议和内容安全策略，不能把结构化JSON碎片显示给学生。

## 7. 标准错误语义

统一`{error:{code,message,request_id,details}}`，details不得含PAT、完整上游正文或个人敏感资料。建议码：UNAUTHORIZED、FORBIDDEN、REVISION_CONFLICT、IDEMPOTENCY_CONFLICT、KNODO_NOT_CONFIGURED、KNODO_CONTRACT_UNVERIFIED、KNODO_AUTH_FAILED、KNODO_QUOTA_OR_RATE_LIMIT、KNODO_UPSTREAM_UNKNOWN、AGENT_OUTPUT_INVALID、STALE_RESULT、SOURCE_UNAVAILABLE、CODELAB_UNAVAILABLE、RUN_TIMEOUT、RUN_OUTPUT_LIMIT、SYSTEM_GRADING_ERROR。

没有真实上游依据时不可把所有429都描述为“余额不足”；把HTTP事实和平台返回码分别保存。连接可能已提交而响应丢失时为UPSTREAM_UNKNOWN，不能默认任务没执行而无限重发。只有明确安全重试的错误才有限退避，必须记录attempt与累计预算。

## 8. 验证与版本

AI输入输出schema、来源映射、允许集合、phase状态迁移、时间限制均有正反例。T03新增模式时同步：Schema→Pydantic→前端生成类型→平台系统提示词/Skill→样例→回归。包里初始枚举不因某个页面方便就单独修改。`contract_version`变化时旧远端会话是否复用由绑定策略决定，不盲目沿用。
