# 迁移、课程生产与多模态交付

## 1. 迁移不是复制旧数据库

T00先读取本机旧仓库的位置、HEAD和未提交修改。不假定旧K12就一定在某个目录：优先检查用户明确路径/已有项目列表，找到后登记`source_roots.json`；找不到时只读获取提供的公开仓库，记录实际ref。禁止在旧仓库pull/reset/clean、迁移数据库、运行seed或改锁文件。

只迁移已审查的源资产。新项目无原学生数据迁移需求，禁止顺手导入旧库171本含测试夹具的书、用户、会话、向量和测试存储。[F2附录D] 本计划沿用的是课程源，实际导入数量由T00本地核对，不把报告数字硬编码为不可变真理。

## 2. 复用清单

| 来源 | 新项目位置建议 | 操作 |
|---|---|---|
| K12 `backend/data/library/manifest.json` 与 `books/**` | `curriculum/source/legacy/` +转换后的`curriculum/published/` | 保留原文/slug/来源，解析伪指令、映射章节/知识点，生成校验报告 |
| K12静态图解/形象素材 | `curriculum/assets/`或`frontend/public/` | 检查授权、实际存在、SVG主动内容；保留归属说明 |
| K12 `data/library/assessments/**` | `curriculum/questions/drafts/` | 继承DRAFT，不自动APPROVED；逐题人工审校 |
| K12 `data/codelab/tasks/**` | `curriculum/code-tasks/` | 迁移三题/参考实现/测试语义，增加明确课程关联；原题不相关则另增真实任务 |
| K12评分/校验纯函数及测试 | `backend/app/modules/codelab/` | 小块复制后改依赖并跑测试，保留来源注释，不搬旧config全局对象 |
| K12沙箱与执行测试 | `runner/` | 复用安全约束与测试思想，重新核查IO/挂载/清理/结果可信边界，不逐字照搬缺陷 |
| CareerMate任务上下文/候选思想 | `backend/app/integrations/knodo/`与业务候选服务 | 用Python/Pydantic重实现等价边界；不跨语言机械翻译整个服务 |
| CareerMate平台素材打包与评测组织 | `platform/knodo/`、`scripts/` | 借鉴源码可追溯打包，不导入百宝箱工作流格式或旧令牌 |
| 旧测试场景 | 新`tests/`和`e2e/` | 把目标语义迁移成新契约测试，不沿用通过统计 |

不迁移：`.env`、node_modules、.venv、旧DB、旧向量、未审原始个人材料、全套历史迁移、百宝箱API wire、旧Agent框架空壳。每项选择写`MIGRATION_MANIFEST`含source_sha/path/hash/new_path/reason/changed_contracts/test_evidence。

## 3. 唯一内容主源

`curriculum/source/`是可编辑课程源；经过审校后构造不可变`release_id/revision`快照，同一快照供本地阅读与Knodo教学包。修改生成新版本，不原地覆盖学生正在学习的正文。旧lesson保留它开始时版本；是否切新版本必须显式告知并刷新远端绑定。

每份release登记：课程/章节稳定ID、适用阶段和年级、目标、先备知识、原始来源、授权状态、review_status、reviewer、文件hash、资源关联、知识点与题目/任务关系。空值保留UNKNOWN，不能伪造出版社、专家或授权。

export-knodo只导出学生可见正文、教学目标、受控资源清单和对应来源定位；不导出标准答案、隐藏测试、真实学习数据。导出清单和上传版本必须对齐。平台知识库的文件搜索能力不自动等于带学段权限的RAG，优先由后端选片段；只有实际验证后才允许平台从挂载的课程范围补充检索。

## 4. 四个示范章节

| 学段 | 初始方向建议（不是已有课程的事实） | 必须展示 |
|---|---|---|
| PRIMARY_LOWER | 用生活实例区分“按规则分类”与“看例子学习” | 适合1–2年级的短语句/图示/一次一个判断；新内容真实审校 |
| PRIMARY_UPPER | 排队、比较与排序的直观过程 | 可控相邻比较动画、排序卡片、针对错误反馈 |
| JUNIOR | 从已存在Python入门/查找材料选一章 | 章节上下文、真实代码运行、报错定位、解释后练习 |
| SENIOR | 从已有机器学习/算法内容选一章 | 概念边界、数据/算法实验、结果解释；不要求复杂模型训练 |

具体章节标题和来源由T01选择并登记，不能把本表建议题目说成仓库原文。初期优先做深高小和初中两课，同时为另外两档建立合格的真实样例；最终四档至少各一节可完整演示。这些数量是本项目验收目标，不是官方最低数量。

## 5. 五类交互的真实交付

①对话：Knodo目标Tutor实际调用，带本章来源、不同年级策略、错误反馈；不是固定mock文本。

②教学资源：至少一份可打开的Word、一份可打开的PPT和一个真实教学视频（或同范围自制教学视频），关联章节、授权与发布状态。允许预上传已有资源，不强求实时生成这三种格式。新系统应支持安全预览/下载与视频实际播放；不能用“播放”按钮打开空白链接冒充完成。Word/PPT预览转换可在管理端离线完成，浏览器可下载原件；转换失败时如实显示下载而不声称在线预览。

③动画：至少两个教学概念的固定模板组件，例如排序步骤与二分查找区间。知识步骤由确定性函数生成，支持播放、暂停、单步、重置；讲解对应每步。UI雪碧图、按钮动效不计教学动画。模型只能填受约束参数和解说，不运行任意HTML/JS。需验证初始/末尾/重复值/空输入等边界。

⑤编程：至少三项带starter code的真实任务，至少一项绑定示范章节；可以写、运行、看报错、重试、查看AI建议和可信测试结果。参考答案/隐藏测试不对学生端公开；容器不可用明确失败。

⑥趣味练习：讲解后按本章生成或选择题目、分层提示、自动批改；至少排序或匹配一种操作活动，以及普通选择/判断。小徽章和鼓励文案可用，但不是核心；不建立竞争排行榜。是否AI生成、模板、人工题库均如实标明。

④绘本（O01）：只有真正图文分页且含互动时算图文绘本；若只预置图文阅读，不宣称动态生成。要求生成时，应有按主题组装/生成的文字、页序、真实授权插图和来源记录；没有图像工具可使用审核素材映射，不能空白占位或把分镜文字说成配图完成。

## 6. 教研草稿→发布流程

Designer生成结构化规格或实际文件，任务登记DRAFT与平台run引用。后台检查真实文件存在、格式、大小、hash、可打开、来源、内容准确性，再交人工review。自动校验仅AUTO_VALIDATED，人工才可HUMAN_APPROVED→PUBLISHED。审核操作写actor/time/revision/comment，不允许Bot写审核人字段。

若平台没有生成文件下载契约，仍可让Designer返回LessonPackageSpec，再由本地受控模板生成页面/动画数据；标明这是“平台生成结构化规格，本地渲染”，不是“平台直接生成视频”。输出格式受白名单限制，拒绝任意脚本、外网依赖或越权路径。收费或长任务在PG worker中执行，不把一次网页请求一直挂住。

平台返回的文件路径/URL未必公开稳定。下载器仅接受官方核实的授权文件接口/域名，检查重定向、大小、内容类型、防路径穿越；归档到本地资源ID后再关联课程。不得用通用任意URL抓取器绕过权限。

## 7. 内容质量检查

题目应能从给定课程与推导得到答案；选择题选项唯一键、单选唯一答案、排序无重复缺项；提示三级逐渐增加信息而不第一层暴露完整解。算法讲解必须核对每步及边界。低龄材料须人工检查读写负担，不靠“句子变短”就认定适龄。

本地测试可用明确标记的合成课程跑通schema和UI，但不能把合成fixture自动转为已审校示范课。报告分开“内容结构合法”“模型生成可用”“人工内容审校”“真实学习效果”；四者互不代替。


## 开发测试例外：合成课程不是人工审校课程

为了不让人工审校阻塞骨架开发，允许在明确的开发/测试profile中加载带`is_test_fixture=true`的合成课程和试验资源，界面始终标为“测试内容，未作人工教学审校”。它不获得HUMAN_APPROVED，不进入正式课程发布目录，正式profile拒绝使用。浏览器功能测试可以使用这种测试内容；测试通过不等于四档示范课已经完成。

真实Knodo的小样本技术验证也可以使用明确标记的合成教材和合成学生，记录为LIVE_TECHNICAL_SYNTHETIC；最终教学样板和参赛内容验收仍需真实审校。使用真实模型不自动把测试课程转成已审校教材。
