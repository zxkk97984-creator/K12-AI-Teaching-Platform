## 结论

**保留现有计划，增加协作治理，不重新架构。** 产品和技术由既定计划约束；监督者负责派发一项、独立复核、记录进度，执行者负责实现和自测。两者不共同编辑业务源码，也不同时运行会写同一测试库/构建目录的命令。

已有34项核心任务T00—T33和4项可选O01—O04不变。用户最后明确报告T00—T05完成；实际接入时以本地progress和证据为准，不能把本包当作已执行T06的证据。

本包是工作方法、Prompt、逐任务对照卡和辅助检查工具，不是新的Agent运行平台，不是Herdr插件，不会自动安装、调用模型、修改项目、解锁门禁或创建真实派工。

## 两个窗格

使用两个现有Herdr窗格：A监督者、B执行者。你已启动的执行者应优先复用，不再重复创建。两边都在目标项目目录启动各自CLI，可以使用同一DeepSeek模型；监督角色不被假设为能力更强。

先给B发送 `prompts/02_EXECUTOR_BOOT.txt`：只登记就绪、接收规则、等待派工。
再给A发送 `prompts/01_SUPERVISOR_BOOT.txt`：核对实际任务状态、Herdr连接、两个窗格和协作约定，派发当前合法任务。

启动Prompt是本次用户明确选择双Agent模式的实现。两边必须确认 `ROLE_OVERRIDE.md`：**旧Prompt中“执行者更新progress、自己找下一项”的职责转交给监督者。** 业务验收条件、原任务依赖、技术栈和五个真实性门禁完全不降低。

## 批次

默认先推进M1剩余任务，通常T06—T08：每项自测后独立复核，失败回修；M1完成后做集成复核，报告后暂停。用户只需在阶段结束后发“按原计划继续下一阶段”，不再逐任务搬运长Prompt。

需要跨阶段自动推进时，使用 `prompts/05_CONTINUE_BATCH.txt` 中的ALL_ELIGIBLE方式明确授权。该方式只推进原图允许的任务，不授权平台消费、真实学生数据、人工审校、公网上线或可选任务。

## 不能误解的事情

- Herdr的done/idle/blocked是终端观察信号，不是某个dispatch通过验收。
- 文件回执也不是质量保证，监督者必须检查实际源码、测试、版本和副作用。
- 文件所有者分工、flock和哈希是协作约束/变更检测，不是两个同权限进程之间的强安全隔离。
- 当前环境未在你的电脑安装或实测Herdr。需要现场核对安装版本、自带Skill和CLI帮助；无法送达时不能假装自动协作已建立。
- Herdr不是关机后仍能运行的计算资源。电脑关机/休眠、进程或网络中断都会影响实际工作；终端恢复后依据文件续接，不重复派工。

离线检查结果见 `evidence/LOCAL_VALIDATION.md`，与新项目真实验收分别记录。
