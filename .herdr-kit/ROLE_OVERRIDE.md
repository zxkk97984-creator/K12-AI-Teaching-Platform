# 双Agent职责补丁：必须先由两个角色确认

适用：用户已选择本包双Agent模式且两边启动Prompt均完成后。未切换的旧会话必须先暂停，不与本流程并行。

本补丁只改变**执行责任与完成流转**，不改原任务业务目标、前置、门禁、QA或锁定架构。若与更高层环境权限冲突，停止并说明，不绕过。

1. 原逐任务Prompt中的“更新.rebuild-kit/progress.json”由A监督者执行。B只写自测报告与SUBMITTED回执；A独立审查后才写DONE。
2. 原“完成后选择下一任务”的权力归A。B没有有效新dispatch就停止业务写入，不自行T06→T07。
3. 原只读审核模板的“不得修改progress”在**复核进行中仍然有效**。A先保存不可覆盖的复核结果、结束复核，再进入单独的进度登记步骤；只有原验收全部通过才登记DONE。复核发现问题时记录FAILED/BLOCKED及依据，不更改门禁骗过依赖。
4. 原“通过后不自动继续”在已明确授权的批次内替换为：A完成证据登记后可派下一合法任务；默认到阶段集成验收报告为止暂停，不自动跨阶段。
5. 唯一业务代码写入者B，唯一任务进度/批次控制写入者A。各自只写自己的交接记录，A不编辑B的提交或旧报告，B不编辑A的复核。
6. 测试库/构建/迁移串行且采用协作锁。审核期间B不写源码、不跑生成器、不留后台自动格式化/测试watcher继续写文件。已有无写入开发服务可保留，详细清单必须交接。
7. 原状态只用NOT_STARTED/IN_PROGRESS/BLOCKED/DONE/FAILED。ACK/SUBMITTED/REVIEWING等仅用于.herdr-control交接，不写进原任务status。
8. 命令、模板或Herdr状态不构成付款/公网/真实学生/人工审校授权。外部服务预算须覆盖A复核和B测试总量，两人不得各用一次“完整预算”。

启动时两角色各自写一个role_ready回执，包含读到的本文件SHA-256、角色、真实pane标识和项目realpath。缺任一回执不派业务任务。根AGENTS.md无需自动覆盖；它与本最新角色指令存在无法解释的硬冲突时，记录并请求解决，不默默改文件。
