## 4. B实施步骤（沿用原续作Prompt）
1. 在T11/T12/T08及原卡门禁均有证据后，从一个明确课程revision和两个合成学生开始。允许原计划的技术测试课程例外，但必须LIVE_TECHNICAL_SYNTHETIC标记，不算正式教学样板审校通过。
2. 从浏览器选章发送到本地run、平台Bot、回传验证和数据库保存，逐跳保留实际关联；不能只在终端curl接口后说页面已通。
3. 检查目标Bot/Skill/课程包确实生效，来源内容与本章吻合；测试无材料的问题，不能只看Bot自称身份。
4. 至少两轮续聊，交替A/B，测试并发、换章、修改年级、Bot配置版本变化和旧结果返回；日志记录实际绑定而非学生可选remote_id。
5. 按授权和平台能力核对历史工具、共享目录、记忆和执行权限；模型口头拒绝与工具技术上不可越权分别记录，不能据一次测试全量宣称隔离已证明。
6. 记录所有样例的输入范围、来源版本、事件、首段有效内容时延、总时长、实际usage或unknown、失败与消耗；停止条件在预算内。

## 5. A独立复核重点
非只HTTP200；双学生及配置版本验证；费用与等待口径准确；未知信息和串用户须失败；不可把技术测试写成低龄开放。

以下原反例逐项核对，不只看执行者报告：
1. 一条实际浏览器→Knodo→本地持久化→浏览器展示链完整，有来源和部署证据。
2. 续聊/换章/版本变化表现正确，未提供信息不编造引用。
3. A/B无可观察串用，已测试和未覆盖的权限面分别列出。
4. 失败输出、坏JSON、取消、超时不写成功或无限重试。

## 6. 原QA口径
| ID | 场景 | 可观察预期 |

| QA06 | 切学段/版本/章节 | 新策略生效；旧run变STALE；不把旧反馈写新课 |
| QA14 | 两个合成学生交替/并发/换账号 | 本地与远端绑定无串用；共享工具/文件/记忆另核对 |
