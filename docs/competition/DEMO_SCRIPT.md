# 比赛演示脚本

更新日期：2026 年 10 月 3 日。配套材料：[项目报告](REPORT_DRAFT.md)、[本次截图与验证记录](../../frontend/test-results/competition-evidence-20261002/EVIDENCE.md)。

## 准备

首次执行 `./k12 setup`，之后用 `./k12 start --build` 启动，使用 `./k12 status` 确认服务。
需要编程执行时改用 `./k12 setup --with-runner` 和 `./k12 start --with-runner`。
已有开发服务可直接复用，不必重复初始化。

准备专用演示账号、已发布或明确开启本地演示可见的课程、互动内容和练习。按现场网络选择真实 Knodo 或离线 fixture，
明确说明当前模式。学生登录后进入 `/workbench`，管理员进入 `/admin/resources`；
未完成首次设置的学生先选择年级。账号配置见[本地开发说明](../operations/LOCAL_DEV.md)。

先查看页面显示的具体年级，不能用账号名字推断学段。本次取证时，配置名为 `DEMO_STUDENT_JUNIOR` 的账号实际档案是高一；演示和截图均按页面的高中状态介绍。需要四学段对照时使用事先准备好的合成账号，或在演示前确认年级并新建会话；已有会话保留原教师快照。

现场开场可说明：“今天展示的是本机可运行原型，教师回复使用当前配置的 Knodo。动画与绘本为预置内容，正式练习和编程由服务端判分。自动化测试使用的 fixture 会单独标注。”如果切换离线模式，修改这段话并重新启动；不要只修改口头说明。

语音使用日常 Edge 或 Chrome。在学习设置启用输入和输出、选择普通话声音，先试读一句并说一句合成问题；识别后修改草稿，再手动发送。自动读新回复需另行开启，默认关闭。现场没有声音或权限被拒绝时，使用键盘和讲解文字，明确说明实际状态。

## 现场时间安排

| 环节 | 页面与内容 | 建议时间 | 展示重点 |
| --- | --- | --- | --- |
| 进入学习空间 | 首页、当前年级和资源库 | 1 分钟 | 账号与学段真实匹配，说明教材来源 |
| 读懂并动手 | 原创教材目录、章节、AI 认图片或水果分类 | 2 分钟 | 来源、版本、动画、字幕及实验保存 |
| 向教师提问 | 新会话，一个 AI 通识问题或三类查询 | 操作 1 分钟，模型等待另计 | 当场回复与预制内容分开，查看状态和来源 |
| 巩固与反馈 | 已有练习；必要时现场生成一题 | 1—2 分钟，出题等待另计 | 学段题量、提示、服务器批改、错题入口 |
| 编程实践 | 代码框架、公开示例、正式判题与记录 | 2 分钟 | 示例不计分，可信成绩与 AI 建议分别说明 |
| 记忆与管理 | 来源、更正、遗忘和后台配置 | 选讲 1—2 分钟 | 先看已准备的合成记录；真实提取需等待 |

页面与操作约 7—10 分钟，真实教师和题目生成等待另计。模型尚未完成时可切换展示已准备的动画或代码页面，返回同一会话查看最终状态。预先准备的回复必须说明它的日期与模式，不能当作本次现场生成。新录的浏览器证据验证页面和操作；完整语音及模型时延以当次实际结果为准。

## 建议演示顺序

1. 展示学习首页，再从 `/settings` 更换具体年级，说明小学低段、小学高段、初中、高中的首页与导航差异。保存昵称、教师风格或桌宠，刷新确认账号设置保留。
2. 从 `/resources` 或 `/study` 打开资料、课程、书架和阅读历史。小学可展示绘本续读；教材阅读可展示目录跳转和“问问老师”，再展开、收起一道固定自测题的参考答案；说明这里不做在线判分。
3. 打开 `/conversations`，不选课程直接提问，再切换历史会话。分别使用小学、初中、高中演示账号，展示对应教师名称和讲解风格；小学低段和高段共用小学教师。展示桌宠中的轻量提问与完整对话页；输入“查课程、本人错题和学习进度”，查看查询时间并点击结果卡片。语音是否可用以当前浏览器能力和权限为准。
4. 在章节页点击桌宠，说明老师会收到发送时的页面上下文。发送“给本章出 10 道题”，展示分批生成进度，完成后直接在同一对话中作答、查看批改并追问。刷新后恢复同一题组；切换章节后保持对话，更新当前参考。小学低年级、小学高年级、初中和高中均支持自选 1–20 题。
5. 小学从 `/animations` 或 `/practice` 进入已发布的互动讲解或小游戏；初高中从 `/activities` 进入互动探索。十二份讲解自然结束后显示“已看完”，继续“自己试一试”、保存、刷新确认实验输入恢复；已看完不代表掌握或成绩。小游戏另按原有完成规则演示，保存失败时展示重试。
6. 从教师回复生成练习，或在 `/practice` 选择章节生成。小学先选“老师给我的练习”。展示现有单选、判断和排序，答题、查看提示和服务器结果，再提问“查本人错题和学习进度”，点击卡片回到对应练习；生成失败如实展示，不能用示例题冒充实时生成。
7. 初高中进入 `/code`，展示各学段 6 道题的搜索、筛选、收藏和历史。保存草稿后运行公开示例，再提交正式判题；公开示例不产生分数，正式成绩来自 runner 的可信用例，AI 建议不改变成绩。
8. 在聊天中明确说“我喜欢观察星星，希望用生活例子讲解”。进入 `/growth` 查看整理进度，等待自动条目及来源出现；新建会话提问，让教师结合兴趣举例。可切换年级后新建会话，说明教师共享同一账号的记忆。更正兴趣后再次提问，再执行遗忘并确认后续上下文不再使用该条目。整理失败如实展示并重试，不把 fixture 提取冒充真实模型结果。
9. 在 `/growth` 展示手写 Markdown 的编辑、预览和版本恢复，以及分类搜索、自动整理／聊天使用记忆两个开关、主动整理历史聊天、删除聊天时的保留／遗忘选项。手写内容不会被自动总结覆盖。
10. 管理员打开 `/admin/ai`，展示教师、四学段映射、能力登记、远端核验和合成协议测试。调整路由后新建会话即可生效；已有会话保留教师快照。再展示 `/admin/resources/interactive` 导入发布。课程编排和教学包生成已从常规入口隐藏；需要查看已有教学包时，使用原 `/admin/authoring?job=…` 地址，不把历史结果当成本次生成。

## 推荐与未完成能力的说明

首页 `/workbench` 的“接下来学什么”展示后端建议，`/learn/next` 可查看理由、依据、兴趣备选和忽略／恢复状态；`/learn` 仍跳转到 `/study`。2026-10-03 已在隔离 API/PostgreSQL 中验证“答错—首页建议—直达原题—重练答对—建议变化—刷新保持”，教师及题目内容为 fixture，桌面和 390px 结果见 `frontend/test-results/recommendation-loop/browser-report.json`。

先从左侧“趣味练习”选择当前学段的小游戏、互动挑战，或选择课程章节准备题目；个人题组通过课程、AI 讲解或“历史记录”打开。演示保存退出后，通过独立“历史记录”入口继续练习；按类型、完成状态或题目收藏筛选，各轮真实会话直接逐条显示。完成后“查看结果”进入只读回顾，再练一次保留旧记录。手机端使用“更多 → 历史记录”。

演示时在在线练习中提交一道错误答案，在即时反馈下点击“回首页查看学习建议”，从“查看结果与解析”回看原题，再点击“再练一次”并正确提交。旧错题建议会解除，其他未纠正问题继续保留；一次答对可能转为继续练习，不宣称已经掌握。历史记录尚未整理时点击“更新建议”。设置兴趣和允许使用的有效个人兴趣提供关键词关联的备选，更正、遗忘、过期或关闭个人记忆使用后不再采用旧条目。

配套真实 Knodo 查询已覆盖四学段普通回复、课程、本人错题和学习进度。首轮三项通过、一项失败，小学高段专项复测通过；首轮模型解释触发本地回退，现场仍以本地卡片中的实际状态为准。日志在 `frontend/test-results/recommendation-loop/knodo-live.log` 和 `knodo-upper-diagnostic.log`，不把配置回读或 fixture 当作真实模型验证。

当前绘本是两本预置阅读示例，不能介绍为按 AI 知识点实时生成。Word、PPT 和视频管理接口已有，但本次取证时对应材料均未向学生开放，现场选用实际可打开的教材、讲义和互动内容。真实教学包生成仍未开放，不用 fixture 教学包证明真实 Knodo 生成。

教材中的固定自测只展开参考答案，不记录正式作答或错题；要演示自动批改，进入在线练习。课件“已看完”、HTML 上报分数、服务器练习成绩和 runner 可信成绩各有含义，介绍时保留页面原有标记。

## 答辩重点

- 四学段界面围绕同一账号、课程版本和学习记录展开，切换页面后保留学习过程。
- 三位教师负责教学互动和编程反馈，Designer 负责教研草稿，内部记忆助手返回结构化提取建议；身份、记忆合并、成绩和数据归属由本地服务处理，助手之间不自行派工。
- 互动包在受限播放器中运行；普通 HTML 的自报结果与服务器判分、可信 runner 结果分别介绍。
- 个人记忆按学生隔离，后台整理不阻塞聊天；人工更正优先，遗忘抑制旧消息重新记住。它是带来源的教学参考，不能替代测验成绩或推断人格与能力。
- 真实 Knodo、fixture、浏览器合成测试和历史评测分开说明，不推断未经验证的学习效果。
