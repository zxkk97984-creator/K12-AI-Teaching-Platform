# 本地 Git 与连续执行政策

## 适用范围

本政策记录本轮用户授权：在 `/home/zxk/Projects/K12` 建立本地 Git 历史，
筛查后提交当前状态，并在后续任务中由监督者维护进度和提交检查点。

## Git 边界

- 仅使用本地仓库和本地 `main` 分支。
- 不创建或替换 remote，不 push，不 force-push，不复制旧项目 `.git`。
- 不执行 `reset --hard`、`git clean` 或其他会删除/覆盖用户文件的操作。
- 首次提交是当前状态快照，不表示所有任务通过；T23 若仍在建必须标记 WIP。
- 提交前检查暂存清单、diff、敏感路径、大文件、嵌套仓库和越界符号链接。

## 纳入与排除

纳入业务源码、正式测试、迁移、课程和契约源、锁文件、启动/检查脚本、
脱敏文档、规划材料及真实 `progress.json`。运行时、依赖、数据库、上传文件、
快照、Herdr 动态控制记录、凭据和浏览器状态不纳入。原始 DOCX、二进制技能包等
规划附件单独保留，不因位于项目目录就自动提交。

具体筛选规则由根目录 `.gitignore` 执行；它不是秘密扫描的替代品。

## 协作边界

- A（本 Goal）负责派工、独立复核、`progress.json`、Git 暂存和提交。
- B 是唯一业务代码实施者；B 只写自测报告和提交回执，不写 progress、不操作 index/commit、不自行进入下一任务。
- 同一测试库、迁移链和构建目录必须串行使用协作锁；复核期间源码不得继续变化。
- 任务状态仍只使用 `NOT_STARTED`、`IN_PROGRESS`、`BLOCKED`、`DONE`、`FAILED`。

## 真实性约束

本地代码、fixture 验证、真实平台验收、人工内容审校和真实学生开放分别记录。
不得以 fixture 冒充真实 Knodo，不得由模型签署人工审校，不得在门禁未满足时宣称
T11/T13/T31/T33 或整体项目完成。

## 本轮基线事实

首次基线建立时记录当前日期、仓库状态、当前任务、活跃 dispatch、T23 未完成范围、
测试来源和未验证项。不得倒造 T22 结束时的历史提交；后续任务按真实 diff 建立独立检查点。
