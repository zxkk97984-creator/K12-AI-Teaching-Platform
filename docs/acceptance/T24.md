## 实现与边界

- `runner/Dockerfile` 使用固定 digest 的 `python:3.12-slim`，无第三方包；实际构建
  镜像 `k12-codelab-runner:0.1.0`，用户为 `65532:65532`，entrypoint 固定为
  `/runner/worker.py`。构建 digest 与 worker hash 记录在 `runner/image.lock`。
- `runner/host/runner.py` 只接受 allowlist 中的 T23 任务/revision、单个 JSON 输入、
  受限代码、owner/lease；拒绝 image/volume/command/env 等请求字段。Docker 不可用或
  固定镜像缺失时返回 `RunnerUnavailable`，不回退宿主 Python/subprocess 执行。
- 容器实际使用 `network=none`、非 root、read-only root、`cap-drop=ALL`、
  `no-new-privileges`、CPU/内存/PID/墙钟超时限制和有大小上限的 `/tmp` tmpfs；只读
  bind mount 当前 case request 与 student source，不挂全仓、不挂 Docker socket。
- stdout/stderr 使用 selectors 流式读取，达到上限即终止；容器 worker 自身也用有界
  TextIO 捕获学生输出。每个容器只拿一个 case 输入，不拿可信 oracle 或隐藏 case 列表。
- 任务、owner、lease、instance 标签齐全；清理按精确 project+owner label，只回收已停止且
  lease 过期的自有容器，不处理活动容器或其它项目容器。

## 首次失败与修复

1. 第一次专项脚本在 pytest 导入应用前失败，因为脚本没有显式要求项目测试环境的
   `APP_SESSION_SECRET`/`TEST_DATABASE_URL`；修复为显式 fail-closed 检查，并仅在本次命令
   通过既有 `/tmp/t20-env.sh` 载入环境后重跑。
2. 清理测试第一次把 Docker `run` 返回的完整 ID 与 `docker ps -aq` 的短 ID直接比较；清理
   已正确删除目标容器，修复测试为 Docker ID 前缀等价比较并补充删除后 inspect 失败断言。

## 未验证与限制

- 本地容器限制是必要防线，不是“绝对安全”证明；内核/daemon 漏洞、侧信道和公网运营仍未验证。
- runner 尚未接入 CodeLab HTTP/API、持久 run 状态或 T25 的可信判分桥接；本卡只验证 runner
  返回结构化 observation，学生 stdout 不作为判分 oracle。
- T28 仍需完成跨用户、文件/会话/秘密隔离与数据治理回归；T29 负责正式部署/worker 编排。
- 缺 Docker/镜像在本单测中明确失败关闭；本报告的 live PASS 仅适用于已构建上述固定镜像的本地环境。
