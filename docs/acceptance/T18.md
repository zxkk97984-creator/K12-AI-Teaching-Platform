## 3. 设计要点（与 K1–K11 的对应）

1. **事件去重 + 可回查（K1/K8）**：每个可信事件投影为一行，`dedup_key = "{quiz|lesson}:{kind}:{source_event_id}"` 唯一，`INSERT … ON CONFLICT DO NOTHING`；`source_ref` 保存 quiz_session_id / question_id / lesson_session_id / reference，`GET /growth/evidence/{id}` 可回查原始题目或活动；`projection_rule_version` 记录规则版本。
2. **版本化定性观察（K1/K4/K6/K7）**：按目标聚合 QUIZ_ANSWERED，等级只取 `INSUFFICIENT_EVIDENCE / EMERGING / CONSISTENT`，附 `answered/correct/distinct_questions/hints_viewed` 与 `thresholds_version`、`effect_verified=false`；`fingerprint`（规则+等级+证据 id 集合）唯一 → 同事实重复投影不产生新版本，基据变化才新增版本并把旧行标 `superseded_at`（历史保留）。**不存在任何百分比/智力/性格字段**；0 条真实作答时不给结论，overview 明确 `insufficient_evidence=true` 与「仍需观察」文案；`counts_not_effect_notice` 说明条数≠学习效果。
3. **上下文只注入有效证据与 ACTIVE 记忆（K3/K10）**：`build_learner_context` 只取已投影证据 + `status=ACTIVE` 记忆，最多 6 + 4（≤ 契约 12）；注入走既有 `evidence[]`，并把**本次注入 id**并入 run-local `allowed_evidence_ids`，响应校验仍然只允许这些 id（模型不能自造依据）。不搬聊天：只搬结构化条目，不发送学生消息正文/档案。
4. **记忆状态机与历史（K2/K5/QA21）**：`CANDIDATE →(CONFIRM)→ ACTIVE`、`ACTIVE →(DISPUTE)→ DISPUTED`、`DISPUTED →(CONFIRM)→ ACTIVE`、`EDIT` 保持状态并 `revision+1`（`statement_before/after` 进 `memory_events`）、`FORGET` → `REMOVED` 且终态（再操作 409）。候选由两条**本地确定性规则**产生（答错后同一题再答对 / 看提示后同目标答对），从不使用模型；`(owner, derivation_key)` 唯一 + `ON CONFLICT DO NOTHING` ⇒ **同一建议一旦被遗忘，重放旧事件甚至新增证据都不会复活**（规则键不含内容，属有意最保守选择）。
5. **撤回范围如实表述（K12 后半）**：`GET` 返回 `remote_residue="NONE_LOCAL_ONLY"` 与 `local_withdrawal_notice`：本版本没有远端记忆同步，因此不存在远端副本；若将来接入平台侧记忆，需按平台能力单独撤回——**不宣称物理清除了其它系统的记录**。
6. **读接口不生成（K4）**：`GET /growth/overview` 只读（测试断言首次读后 `learning_evidence_items` 仍为 0）；只有显式 `POST /growth/projection`（CSRF）或 tutor run（事件触发）才投影。
