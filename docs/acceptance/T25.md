# T25 验收报告：可信判分与 Knodo 代码辅导边界

- 任务：T25 / M5
- 基线：`9682b15`（T24 本地提交）
- 复核方式：当前单 Agent 完成第一遍实现后停止修改，按原卡做第二遍自我复核；不是独立 Agent 审核
- 结论：**本地可信判分/反馈边界通过；真实 Knodo CODE_FEEDBACK 仍 NOT_RUN/BLOCKED**

## 实现范围

`backend/app/modules/codelab/feedback.py` 将 T24 runner 结果、T23 trusted grading 和 Tutor
反馈绑定到不可混淆的 `owner_id/run_id/task_revision/code_hash` 快照：

- runner 状态映射为 `SUCCEEDED/FAILED/TIMEOUT/OUTPUT_LIMIT/SYSTEM_ERROR`，可信正确性只来自
  `GradingResult`，学生 stdout/“pytest 通过数”只作为有界诊断摘录，不能成为 oracle；
- `build_feedback_request()` 只写入冻结 `teaching-request` 的 `code_feedback_facts`，要求
  `CODE_FEEDBACK` operation、当前任务 allowlist 和当前认证 owner；不包含 reference solution、
  hidden tests 或他人记录；
- `TutorFeedback` 使用 extra-forbid schema，禁止 AI 返回 score/grade 等字段；行号必须落在
  发送给 Tutor 的代码 excerpt 范围内，run/code hash 不匹配或编辑后旧反馈会被拒绝；
- `public_code_run_projection()` 永远分别返回 deterministic score/status 与 AI feedback 状态，
  AI 缺失/失败不会补 0、覆盖可信失败或伪造综合分；反馈幂等 key 绑定 owner/run/code_hash；
- 现有 `Operation.CODE_FEEDBACK` 和冻结 `contracts/teaching-request.schema.json` 未修改。Gateway
  `knodo` 仍 `NOT_IMPLEMENTED_T11`，没有增加直连模型或真实平台 fallback。
