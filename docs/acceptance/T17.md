## 3. 交互与数据流（与 J1–J12 的对应）

1. **明确点击即授权（J1/J8）**：lesson 页「开始练习 / 按老师的建议开始练习」= 一次明确点击 → `/practice?…&start=1` → 页面落地即建一次会话；参数在 POST 前被 `history.replaceState` 抹掉，刷新只会恢复不会重开。直接访问 `/practice`（无 start）只显示「开始练习」活动按钮、不建会话；已完成时提供「再做一组练习」显式新建。
2. **服务端驱动（J3/J6）**：hint 按钮文案/禁用来自 `hints_used/hint_limit`；级别 = `hints_used+1`（只做显示推算，服务端仍校验顺序与上限）；attempts 显示 `attempts_used/max_attempts`；提交后**重新 GET 会话**再渲染，前端从不比对答案。
3. **反馈与复习（J4）**：赞/误判由 `feedback.outcome/is_correct` 驱动，含服务端 `correct_answer`、`explanation`、来源 `source_refs`；错答 → `GET /review` 展示 `reason/objective_id/similar_source/next_action/thresholds_version/effect_verified=false`，并提供 `回看课文`（`/chapters/{chapterId}`）与「再做一组」；「回课堂继续」跳回**同一** `/lessons?session=<同一 lesson session>`。
4. **刷新/换号（J5/J10）**：只缓存 quiz id 且按 user id 命名空间；任何读之前 `adoptUser` 清理其它账号命名空间（不依赖旧 marker）；后端 owner 校验保证 404。
5. **不做虚假激励（J11）**：结果区只渲染服务器 `progress`（作答/答对题数），文案明确「不是对你能力的评价，也没有任何奖励或名次」；无排行榜/正确率/积分/掌握度。

## 4. 前端单测（新增 16 条，`npx vitest run src/features/quiz/quiz.test.tsx`）

- 入口授权：直接访问不建会话；同一次点击两次只 1 次 POST；`start=1` 建 1 次并抹参数；建后写入按用户命名的 cache
- 恢复与隔离：命中 cache → 走 GET 不新建；服务端 404 → 清条目并给「重新开一组」；换账号 → 其它命名空间被清空且不读取对方会话
- 服务端驱动：提交 payload 形状（单选 key / 判断 **boolean** / 排序完整 key 数组）；判分结果只来自刷新后的 DTO；**无服务端 feedback 时前端不渲染任何对错**；提示按钮按计数驱动并禁用；失败保留草稿且重试复用同一 `idempotency_key`
- 结果与复习：结果数字来自 DTO、禁止词扫描（排行榜/正确率/掌握度/积分）、review 链接与 `effect_verified=false`、回跳同一 lesson session、显式点击才新开一组
- 回归：1 题会话已结束但 `attempts_left>0` 时**不得**承诺「还可以再试」（浏览器链发现的真实缺陷，见 §5 失败 3）

## 1. 阻塞事实（可复现）

T17 的交互闭环要求「作答 / 提示 / 反馈」全部走后端真实结果（H/J3、J6、J9）。但 T16 的学生 DTO **不返回任何可被作答/提示路由接受的问题标识**：

- `GET/POST /api/v1/quiz-sessions`（及 `GET /quiz-sessions/{id}`）的每道题字段为：
  `attempts_used, hint_limit, hints, hints_used, max_attempts, options, position, question_key, source_refs, stem, type`
  —— **没有 `id`**（`question_public()` 逐字段构造，未包含 `QuizQuestion.id`）。
- 而作答/提示路由的路径参数是 **UUID**：
  `POST /quiz-sessions/{session_id}/questions/{question_id}/answers|hints`（`question_id: uuid.UUID`）。
- 实测（真实 app + 真实测试 PG + T10 fixture 出题）：
  - `POST .../questions/repro-q1/answers`（用 DTO 暴露的 `question_key`）→ **422 请求参数无效**
  - `POST .../questions/<DB uuid>/answers`（该 uuid 客户端不可见）→ **200**
- 证据：`.herdr-control/evidence/T17-blocker-repro.log`（脚本 `/tmp/t17-dto-repro.py`，日志含 exitcode 与完整输出）

因此前端**无法**在不猜测/不越权的前提下提交任何作答或提示；若强行用 `position`/`question_key` 拼接请求，只会得到 422，并且会违反「反馈来自服务端真实结果」的要求。
