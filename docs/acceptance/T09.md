## 5. 失败与修复（不删失败证据）

1. **反例自测逻辑写反（真实缺陷）**：`selftest` 的"注入密钥"反例把检出结果当作未检出，
   导致该反例恒为 FAIL。修复：改为检测到问题时抛 `CheckFailed`，并**新增干净对照**防止
   "扫描器一律报错"蒙混；同时把该反例改为走真实树扫描器 `scan_package_tree(root=…)`
   （顺带修正临时目录的路径标签计算）。修复后 6 项全过。
   首次失败日志：`docs/integrations/knodo/t09-check.first-failure.log`。
2. **`check.sh` 首次运行 exit=2（环境限制，非代码缺陷）**：沙箱内 `uv` 无法写 `~/.cache/uv`
   （`Read-only file system`）。在授权环境重跑同一命令通过（exit 0）；失败原文保留在同一份
   first-failure 日志中。
3. **更早的样例形状失败（本会话之前）**：`verify` 最初按 `items[].answer` 形状校验，与冻结契约
   `questions[].correct_answer` 不符而失败；已改为契约形状。该次失败**没有**留存独立日志
   （如实标注，不伪造：仅修复后的断言有本报告与日志佐证）。
4. **文档扫描唯一命中**：`docs/integrations/knodo/source-snapshots/llms-full.txt` 含
   形如 `var/lib/docker` 的 Docker 数据目录路径（Knodo 公开文档原文，T02 冻结证据，本卡禁止修改）。判定为公开文档内容、
   非凭据/非交付物缺陷，按豁免登记并打印 ALLOWED EXCEPTION。
