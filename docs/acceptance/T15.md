## 5. 失败与修复（真实缺陷，证据保留）

1. **oneOf 误判未知字段**：`extra_forbidden` 会由不匹配的 oneOf 分支聚合产生（合法排序题也会出现），导致把 SCHEMA_INVALID 误报成 UNKNOWN_FIELD。修复：新增基于冻结 schema 的 `_find_unknown_field()` 走查器（顶层/题型分支/options/items/source_refs），先判未知字段再交给 schema。
2. **判断题字符串被宽松强转**：pydantic 默认把 `"true"` 转成 `True`，伪布尔答案可绕过。修复：语义层强制 `isinstance(correct_answer, bool)`。
3. **测试桩未回显受信 id**：stub 直接返回示例导致 ECHO_MISMATCH。修复：桩按真实 fixture 方式回显 `request_id/chapter_id/curriculum_revision/stage`（测试夹具问题，不是实现放宽）。
4. **expired ORM 属性触发 MissingGreenlet**（测试侧 2 处）：`rollback()` 后读取 ORM 属性。修复：提前取出 `designer_session_id`/`student_id` 等标量。
5. **QA12 断言把字段名当泄漏值**：schema 错误路径里出现字段名 `correct_answer` 属正常诊断。修复：断言改为"被拒字段的**值**与草稿正文不得出现"，而非字段名。
