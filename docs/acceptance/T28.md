## 续作：真实本地数据治理边界

本轮使用合成测试账号和独立测试 PostgreSQL，补充了 `0016_privacy_requests` 与
`backend/app/modules/privacy/`：

- `GET /api/v1/me/data-export` 只导出当前 session owner 的 profile、CodeLab drafts/runs；
  不包含密码哈希、session token、reference solution、hidden tests 或 runner token，并明确列出
  本地 learning evidence 与 Knodo 侧数据不在这个窄范围内。
- `POST /api/v1/me/deletion-requests` 要求 Origin+CSRF，使用 owner+幂等键，执行明确的
  `CODELAB_ONLY` 本地删除；重复请求重放同一审计记录，平台状态固定报告为
  `NOT_CONNECTED/NOT_REQUESTED`，不冒充远端删除。
- 跨账号回归确认：学生 B 看不到学生 A 的 run/export；A 删除后只清掉自己的 CodeLab 数据，
  B 的草稿仍存在；无 CSRF 的删除请求无业务副作用。
