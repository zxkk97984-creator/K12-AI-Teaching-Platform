## 2. 本地实现

### 持久续聊绑定

- 新迁移 `0017_knodo_remote_bindings` 为每个 run 保存：远端 `conversationId`、目标 scope 和脱敏
  远端元数据；`remote_id` 扩到 300 字符以容纳官方未规定长度的 opaque ID。
- scope 由后端固定的 wire 版本、语义契约版本、角色、workspace ID 和 Bot ID 组成；学生请求无法提供或覆盖。
- 下一轮只查询同 owner、同 lesson session、同 scope、`KNODO` 且前一 run 为 `SUCCEEDED` 的绑定。
- 切换章节会创建不同 lesson session；更换 Bot/workspace/契约会产生不同 scope，旧会话不复用。
- 已被上游接受但本地输出无效的会话仍保存审计元数据，但失败 run 不用于下一轮续聊。

### 错误与审计

- mapper 在助手正文不是严格 JSON、finish reason 错误等情况下，仍保留已经确认的远端
  `conversationId`/completion/model/usage 元数据。
- gateway 在本地 Schema 拒绝时不再丢弃远端元数据。
- teaching worker 对成功、失败、取消、依据不足均保存本地 `gateway_invocation_id`；没有真实
  `conversationId` 时不伪造 KNODO 远端绑定。
