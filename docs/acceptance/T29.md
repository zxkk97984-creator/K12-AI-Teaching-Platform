# T29 验收报告：干净部署与唯一初始化

- 任务：T29 / M6
- 基线：`c2eea65`（T28 本地提交）
- 结论：**本地部署范围通过，登记 DONE；真实平台/公网/正式 K12 仍未授权**

## 实际变更

- `scripts/bootstrap.sh` 现在是唯一初始化入口：锁定依赖、等待独立 PG、迁移、导入 legacy
  内容、development/test fixture、CodeLab 任务和可选合成账号；重复运行只 REUSE，不覆盖。
- `backend/app/jobs/worker.py` 提供 durable polling consumer 和 one-shot recovery；部署 profile
  关闭 API 进程内自动执行，worker 承担 teaching/authoring queued rows。
- `backend/Dockerfile` 复用 bootstrap 已准备的锁定 site-packages，使用 digest 固定 Python
  基础镜像；`frontend/Dockerfile` 只服务 bootstrap 构建的 dist，Nginx 反代 API/health。
- `compose.yaml` 新增 API、worker、web、共享 app storage 和显式 env 边界；未把 Docker socket
  挂给 API/Compose，runner 仍是独立 T24 控制平面或明确 disabled。
- `/health/live` 与 `/health/ready` 分离；ready 返回 database/runner/storage 状态，runner 未配置
  时标记 `disabled`，不冒充 runner 正常。
- `AUTHORING_AUTORUN` 是为独立 worker 增加的最小配置边界；默认仍保持既有测试的进程内行为。

## 首次失败与修复

1. 首次应用镜像尝试在 Docker build 中 `pip install uv`，当前构建网络代理拒绝连接；改为
   bootstrap 先按 `uv.lock` 准备 host `.venv`，镜像复制锁定 site-packages，不在部署阶段隐式
   下载依赖。
2. 第二次构建改用 uv builder 后，容器内 Python wheel 下载仍被同一网络边界阻断；保留失败日志
   语义，移除容器内同步步骤，改用本地 bootstrap 产物。
3. web 首次使用容器内 `npm ci`，出现 npm `Exit handler never called`；改为 bootstrap 构建 dist、
   Nginx 只服务静态产物并反代 API。
4. 第一次 API 容器启动缺少 `contracts/`，Knodo 本地 schema registry fail-closed；Dockerfile
   补齐 contracts 后 API/worker 正常启动。
5. 第一次 web smoke 的 Nginx server 缺 root，`/` 出现内部重定向循环；补 root 后首页与 health
   代理均 200。

## 未验证与边界

- 本次 Compose 使用 `runner=disabled` 做部署验收；T24 loopback runner+Docker 已单独真实通过，
  但容器 API 到 host runner 的正式网络接入仍需明确部署授权和地址，不把 disabled 写成 CodeLab
  live ready。
- 未执行真实 Knodo、付费模型、真实学生数据、公开部署或自动人工审校。
- 共享存储只证明本地路径和容器映射；备份/恢复演练与生产编排不在本地 T29 证据中。
