## 4. 原卡验收与通用场景对应

**QA02（重复导入不翻倍，DRAFT 保持 DRAFT）**
- `test_dry_run_writes_nothing_then_import_is_idempotent`：dry-run 前后所有业务表计数不变、镜像目录不存在；第二次导入计数器全部 REUSE，行数不变。
- `test_auto_validation_cannot_publish_and_draft_stays_draft`：导入后是 `UNREVIEWED/DRAFT`；`AUTO_VALIDATED` 不写审核人，且仍然不能发布。

**QA06（修订不覆盖旧版本）**
- `test_new_revision_is_added_and_old_revision_stays_immutable`：新增 r2 后 r1 的 body/hash/知识点关联完全不变；对 r1 直接 UPDATE/DELETE 被数据库触发器拒绝。
- `test_new_revision_does_not_replace_published_version_until_released`：r2 入库后学生仍看到 r1；r2 发布后目录切到 r2，而 `?revision=1` 仍能读到内容未变的 r1。
- `test_same_revision_with_different_hash_is_rejected`：不同 release 携带同一 `(chapter, revision)` 但正文 hash 不同 → 拒绝且库内无变化。
- `test_release_conflict_when_hash_changes`：同 release_key 携带不同 manifest → 拒绝。

**QA24（未发布/撤回/跨学段不可读）**
- `test_unreviewed_draft_is_hidden_and_withdrawal_hides_published`：草稿对所有学生不可见（含按 ID 直读返回 None）；发布后可见；撤回后目录与按 ID 直读（含 `revision=1`）全部不可见。
- `test_fixtures_visible_only_in_development_and_always_labelled`：夹具只在 development profile 可见且带 `测试内容，未作人工教学审校` 标记；formal profile 下完全不可见。
- `test_grade_null_keeps_stage_semantics_and_explicit_range_filters`、`test_explicit_grade_range_outside_student_grade_is_hidden`：无年级只按学段匹配；显式年级区间外不可见；`grade` 无 `stage` 直接非法。
- `test_fixture_content_can_never_be_published`：即使有审校记录，夹具发布被服务层拒绝，绕过服务直接 SQL 改 `PUBLISHED` 也被触发器拒绝。

## 5. 失败与修复（保留首次现象）

1. 转换器首次运行失败：`KC requires 'title :: text' …`——旧语料的 `KC` 用字面 `::` 分隔且段间空格不统一，我最初按 `" :: "` 切分得到 3 段。修复为与旧解析语义一致的字面切分（`title :: text :: label :: text`，4 段才生成 example），并保留“未知标记即失败”。
2. T06 测试首轮 25 passed / 3 failed：
   - 两个用例期望 `RevisionHashMismatch`，实际先触发 `ReleaseConflict`——因为同 release_key 下改正文必然改 manifest hash。修复方式不是放宽断言，而是让用例反映真实模型：新 release key + 同 `(chapter, revision)` 不同 hash 才是修订冲突；同 release key 的改动仍由 `test_release_conflict_when_hash_changes` 覆盖。
   - `test_new_revision_…` 在失败 UPDATE 后访问已过期 ORM 属性，触发 `MissingGreenlet`。修复为在回滚前取出纯 UUID，失败注入与断言不变。
   - 可见性用例写错章节下标（课程文件只有 1 章）。
3. `scripts/check.sh` 首次运行在新迁移文件上因 5 处 E501 失败（保留 `T06-check.first-failure.log`）。仅做换行/格式修复，未改 SQL 语义，随后全绿。
4. `TEST_DB` 误用负例第一次记录时用了系统 `python3`（无 sqlalchemy）构造 URL，导致记录成“缺少 TEST_DATABASE_URL”；已在同一日志里如实标注并复跑得到真实拒绝原因（端口不符）。

没有任何测试被删除、跳过或改期望骗绿；没有 `xfail`、没有提高超时掩盖问题。
