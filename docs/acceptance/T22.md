## 5. 失败与修复（都是先复现再修）

1. **`GatewayResult` 无 `payload` 字段**：`authoring_worker` 直接读 `result.payload` → `AttributeError`，任务异常。按 T15 assessment 的既有用法改为 `result.output` 并显式判断 `GatewayStatus.OK`，失败时记录 gateway 的真实 reason code。
2. **请求体不符合冻结 schema**：`REQUEST_SCHEMA_MISMATCH`。原实现自造 `stage="UNKNOWN"`、空 objectives/knowledge_context。改为新增 `material.py`：按 job 的**精确 revision**加载 stage/目标/正文，拒绝缺失/撤回/无正文（`AUTHORING_REVISION_NOT_FOUND/WITHDRAWN/NO_SOURCE_MATERIAL`），并加契约自检测试。
3. **renderer 按错误形状读取**（把 `teaching_script` 当数组、把动画当 `animation_id/params`）：与冻结 schema 不符。改为按冻结形状渲染（字符串脚本；`template/values/target/narration/source_refs`），并通过资源侧 `validate_params` 映射到已登记定义。
4. **审校只要求"任一个"文件通过**：删掉其中一个文件仍能 HUMAN_APPROVED（V2 反例真实暴露）。改为**所有** artifact 必须回读校验通过；`store_package` 完成后立即全量校验，否则任务 FAILED。
5. **触发器语义过严/过松**：0012 要求 `status='HUMAN_APPROVED'` 导致已发布包不能再发新 revision（V4 失败），且只要求一个 verified artifact。新增 `0013_authoring_guards` 迁移（不再改已应用的 0012）：允许 `PUBLISHED` 续发新 revision，并要求 `verified = artefacts > 0`。降级路径写回旧函数体。
6. **迁移回归测试停留在 0011**：`test_migrations.py` 期望 head=`0011_resources`。更新为 `0013_authoring_guards`，并**新增** authoring 5 张表、14 个 check 约束、2 个触发器的断言（增强而非放宽）。
7. **前端错误文案吞掉了领域码**：`textOf` 把 `AUTHORING_XXX:` 前缀正则剥掉，用户只看到 `REVISION_CONFLICT: 只有…`。改为保留完整 `code: message`（领域码是排障关键）。
8. **（A 在 M4 阶段验收发现）测试自反缺陷**：`test_v8_honest_platform_claims` 断言 `progress.tasks.T22.status != "DONE"`——A 依规登记 DONE 后该断言必然失败。这是把**过程状态**写进产品断言，与实现无关。修复见 §11。
9. **ruff 漏检迁移目录**：只查了 `app/tests`，`alembic/versions/0012|0013` 有 E501。按项目命令 `ruff check backend` / `ruff format --check backend` 修复并全绿。

未采用任何"删断言/放宽断言/提高超时/改 fixture 掩盖"的手段：上述改动均在实现侧或多补了更强断言。
