## 2. 实现

### 唯一 wire mapper

`backend/app/integrations/knodo/wire.py` 将四个冻结 operation 按服务端固定角色映射到：

```text
POST https://knodo.vip/api/v1/bots/{server-owned-bot-id}/chat/completions
```

只发送官方字段：`messages`、`stream=false`、`permissionMode=default`、
`includeToolResults=false`；不发送 `model`，由 Bot 配置决定。续聊只接收网关单独参数中的
后端会话绑定，绝不从学生语义 JSON 读取 `conversationId`。

成功响应必须同时满足：`object=chat.completion`、助手角色、`finish_reason=stop`、非空
`conversationId`，且 `message.content` 是单个 JSON 对象。说明文字、代码围栏、数组、截断、
错误 finish reason、续聊 ID 不一致都会失败关闭，再由冻结业务 Schema 做第二层验证。

### 安全与预算

- PAT 仅来自服务端环境变量；状态端点和证据文件均不输出 PAT、目标 ID 或 base URL。
- base URL 必须是无用户信息、路径、查询和片段的裸 HTTPS origin。
- HTTP 客户端关闭重定向和环境代理；响应先做字节上限检查再解析。
- 401/403、429、5xx、3xx、坏 JSON、过大响应分别归类；读失败/超时标记为“可能已受理”，不重发。
- `FileRequestBudget` 使用进程间文件锁和权限 `0600` 的持久账本；请求在发送前计数，失败、超时或
  取消后不返还；损坏或符号链接账本失败关闭。
- `scripts/knodo-live-smoke.py` 最多执行 3 次：Tutor 首轮、Tutor 续聊、Designer 首轮。脚本无重试，
  只保存请求/输出哈希和非秘密元数据。管理员 PAT 不读取 Workspace 会话历史；Workspace/Skill 绑定使用
  已登录 Edge 的只读页面另验。
