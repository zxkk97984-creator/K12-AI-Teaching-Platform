# ADR-004：R1采用缓冲结构化交付

状态：ACCEPTED  
日期：2026-09-18

## 决策

- R1 默认使用 `BUFFERED_STRUCTURED`：先接收并校验完整平台结构，再通过本地 SSE 发送 `run.started`、真实进度、`message.ready`、`action.ready`、`run.done`。
- 不把结构化 JSON 的碎片直接显示给学生；不把“已收到”显示成虚假进度或工具调用。
- `message.ready` 只在结构和来源校验通过后发送；`run.done` 只在持久化成功后发送。
- 只有在官方 wire 和内容安全策略经真实租户验证后才考虑原生流式（O04）。
- 失败使用统一错误语义；连接可能已提交但响应丢失时记为 `UPSTREAM_UNKNOWN`，不无限重试或重复计费。

## 原因

R1 优先保证学生看到的内容完整、可审核、可回放；流式速度和 token 细节不能换取越权或半截结构。

## 后果

前端需要同时处理本地进度事件和最终结构体，不能把平台 SSE 直接暴露给学生。
