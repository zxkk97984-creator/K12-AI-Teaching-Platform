### 第 1 章 浏览器生成消息

你在浏览器输入 `www.baidu.com` 按回车，浏览器第一件事不是直接去找百度，而是先把这个网址拆解：

- 协议：`http` 或 `https`
- 服务器名：`www.baidu.com`
- 文件路径：`/`（省略时默认主页）

然后浏览器生成一个 HTTP 请求消息，大概长这样：

```
GET / HTTP/1.1
Host: www.baidu.com
```

这个消息会被发送出去。

### 第 2 章 DNS：把域名翻译成 IP 地址

但电脑之间通信靠的是 IP 地址（比如 `180.101.50.242`），不是域名。所以浏览器得先问 DNS 服务器："www.baidu.com 的 IP 是多少？"

DNS 就像电话簿：你记着朋友的名字，要打电话得先查号码。DNS 服务器全球分布，一级一级查，最后拿到百度的 IP 地址。

### 第 3 章 Socket 与 TCP 连接

拿到 IP 后，浏览器要和百度服务器建立连接。这个连接用的是 TCP 协议。

TCP 的思路像打电话：先拨号（三次握手），对方接了才说话；说的时候每句话都确认对方收到了，没收到就重发；说完了双方挂断（四次挥手）。

这样保证数据不丢、不乱序。

### 第 4 章 发送 HTTP 请求

连接建好后，浏览器把刚才生成的 HTTP 请求通过 TCP 连接发出去。数据被切成一个一个小数据包，每个包都编好号，沿着网络一站一站传到百度服务器。

### 第 5 章 服务器返回响应

百度服务器收到请求后，找到要返回的网页文件，生成一个 HTTP 响应：

```
HTTP/1.1 200 OK
Content-Type: text/html

<html>...网页内容...</html>
```

同样通过 TCP 连接发回来。

### 第 6 章 浏览器显示网页

浏览器收到 HTML 文本后，把它"画"成你看到的网页：先解析文字，再下载图片、CSS、JS，最后排版渲染。

这就是你从输入网址到看到百度首页的全过程——前后大概 0.1 秒。

## 补充概念

### IP 地址

IP 地址像门牌号：每台联网的设备都有一个唯一编号。IPv4 是四段数字（如 `192.168.1.1`），IPv6 更长能给所有设备分配。

### 域名

域名是 IP 的"好记版"。`www.baidu.com` 比 `180.101.50.242` 好记多了。

### HTTP 与 HTTPS

HTTP 是网页传输的规则。HTTPS 就是加密版的 HTTP——数据在传输过程中被加密，别人偷看也看不懂。地址栏小锁头就是 HTTPS 的标志。

### Wi-Fi 与宽带

家里的路由器把宽带信号分成 Wi-Fi 无线信号，手机、电脑连 Wi-Fi 就等于连进了同一个小网络。

### 路由器

路由器是家里网络的"门房"：你家设备要上网，数据包先到路由器，路由器再转发给运营商，最后到互联网。
