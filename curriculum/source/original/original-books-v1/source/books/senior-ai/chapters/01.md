# 机器学习解决什么问题

## 学习目标

- 能用自己的话说出“从规则到学习”这个转变，并举例说明为什么有些问题写不出规则。
- 能区分监督学习与无监督学习，并把一个具体问题归类。
- 能把一个现实需求表述成“输入—输出—评价标准”三部分的学习任务。
- 能判断哪些问题不适合用机器学习解决，并说明理由。

## 开始之前

先修要求：会写函数和循环，能读懂用列表和字典表示的数据。本章不涉及数学推导。

热身问题：请你写一段程序，判断一封邮件是不是垃圾邮件。你能写出哪些规则？如果发件人把“中奖”写成“中&#x5956;”或者“仲奖”，你的规则还管用吗？先写下你想到的三条规则，以及每一条会被什么样的邮件绕过。

材料：纸和笔。本章的概念题比代码题多。

## 情景导入

某中学的图书馆想做一件事：根据一个学生过去一学期的借阅记录，预测他下学期会不会借阅科普类图书。

负责的同学第一反应是写规则：“如果这学期借过 3 本以上科普书，就预测他下学期还会借。”这条规则在大多数学生身上看起来挺准。但很快出现了几种情况让他为难：有的学生这学期借了 4 本科普书是因为老师布置了阅读任务，下学期没有任务就不会再借；有的学生这学期只借了 1 本，但借的是他自己买的推荐书单里的；还有转学生根本没有历史记录。

他试着往规则里加条件——“借过 3 本以上**并且**不是老师布置的**并且**是自己挑的”——规则越写越长，每加一条就冒出新的一类例外。最后他意识到：他能说清个别学生的行为，但写不出一条覆盖所有人的规则。

后来他换了个做法：把过去几年几百名学生的记录整理出来，每条包括“这学期借了几本科普书、借了几本其他书、在馆时长、是否参加过读书会”以及“下学期有没有借科普书”。让程序自己从这些记录里找出“哪些特征和后来有没有借之间有关联”。这就是本章要讲的做法——不再由人写规则，而是让程序从数据里找规律。

## 知识讲解

### 从“写规则”到“从数据里学”

传统的程序是你把规则写清楚，程序照着执行。比如“判断一个年份是不是闰年”，规则是明确的：能被 4 整除但不能被 100 整除的，或者能被 400 整除的，就是闰年。这条规则没有例外，写进代码就永远正确。

但很多问题的规则写不出来，或者写出来太复杂。判断一封邮件是不是垃圾邮件、预测一个学生会不会选某门课、从一张照片里认出是不是猫——这些事情人能做得不错，却说不清自己是怎么做的。你无法把“垃圾邮件的特征”列成一个完整的清单，因为发垃圾邮件的人会不断改变写法。

机器学习换了一个思路：**不给规则，给例子**。你提供大量“输入和对应的正确输出”的样本，让程序自己找出一种从输入算出输出的方法。这个过程常常被叫作“训练”。训练完成之后得到一个**模型**，它能对新的、没见过的输入给出输出。

这里有一个必须要说清楚的地方：**模型学到的是数据里的统计关联，不是事情本身的道理**。如果数据里“在馆时间长”和“后来借科普书”恰好一起出现得多，模型就会把“在馆时间长”当作一个有用的线索——它不知道这两者之间有没有因果关系，也不需要知道。这既带来了威力（能处理人说不清规律的问题），也带来了风险（数据里的偶然关联会被学进去）。

### 监督学习：有标准答案的学习

**监督学习**指的是训练数据里包含正确答案。每条样本由两部分组成：**特征**（描述这个样本的各种信息）和**标签**（我们希望模型学会预测的答案）。

情景导入里的任务就是一个监督学习问题：特征是“借了几本科普书”“借了几本其他书”“在馆时长”“是否参加过读书会”，标签是“下学期有没有借科普书”。因为标签只有“有”和“没有”两种，这是一个**分类**任务。

如果标签是连续的数值，比如“下学期会借几本”，那就变成**回归**任务。分类和回归是监督学习的两大类型，区别只在标签是不是连续的数值。

判断一个问题是不是监督学习，只需要问：**训练数据里有没有正确答案？** 有就是监督学习。

### 无监督学习：没有标准答案的学习

**无监督学习**的训练数据里只有特征，没有标签。程序要做的事情不是“预测一个已知类型的答案”，而是“找出数据本身的结构”。

最常见的无监督任务是**聚类**：把相似的样本分到一组。比如把全校学生的借阅记录分成几组，可能发现“只借教辅的”“爱看小说的”“广泛涉猎的”这样的自然分组。这里没有标准答案——没有任何人预先规定应该分成几组、每一组叫什么。分出来的组有没有意义，要靠人来判断。

判断一个问题是不是无监督学习，只需要问：**我们希望模型预测的那个答案，在训练数据里存在吗？** 不存在就是无监督学习。

需要注意一个容易混淆的地方：无监督学习不是“没有目标的学习”。聚类的目标很清楚——让同一组内的样本尽量相似、不同组的样本尽量不同。只是这个目标没有以“标签”的形式写在数据里，而是由算法自己按某个标准“打分”。

### 什么问题不适合用机器学习

机器学习不是万能的，至少有四类问题不该用它。

**第一，规则明确且不复杂的问题。** 计算闰年、按学号排序、把摄氏度转成华氏度——这些问题写几行代码就永远正确，用机器学习反而会引入不必要的误差。用机器学习去解有精确解法的问题，是给自己找麻烦。

**第二，没有足够数据的问题。** 如果一个学校每年只有 5 个转学生，想预测“转学生会不会参加读书会”，5 个样本什么都说明不了。数据太少时，从中学到的“规律”很可能只是偶然。

**第三，数据不能代表使用场景的问题。** 如果训练数据全部来自重点中学，那么学到的模型用在普通中学上就会被误导（这是第三章和第四章会详细讨论的分布偏移问题）。

**第四，涉及重大后果且不能容错的决策。** 比如“要不要给这个学生纪律处分”这类决定，不能让模型单独决定。模型输出的是一个基于历史数据的统计判断，而历史数据里可能包含过去的偏见。这类场景里，模型最多只能作为辅助信息，最终判断必须由人来做，而且要有申辩和复核的渠道。

还有一条容易被忽略的：**如果问题的答案根本不存在于特征里**，机器学习也无能为力。用“借了几本书”去预测“期末数学成绩”，这两者之间如果没有真实的关联（或者关联只在特定条件下成立），模型学到的只会是噪声。

## 详细示例

### 示例一：把三个现实问题表述成学习任务

**问题一：预测期末考试成绩。** 有过去几年学生的数据：平时作业完成率、出勤率、单元测平均分、是否参加过课后辅导，以及期末成绩。

表述：特征是“作业完成率、出勤率、单元测平均分、是否参加辅导”，标签是“期末成绩”。因为成绩是连续数值，这是一个**监督学习中的回归任务**。评价标准可以用平均绝对误差，也就是预测值和真实值相差多少分（取绝对值再平均）。**需要提醒的边界**：这个任务只在“过去的学生和将来的学生情况相似”时成立，如果考试难度或教学内容发生大变化，模型就不可靠了。

**问题二：把图书馆的读者分成几类。** 有每位读者的借阅记录：借了几本小说、几本科普、几本教辅、平均借阅时长、在馆次数。

表述：特征是上述几项，**没有标签**。我们想找出“读者可以分成哪几种类型”，这是一个**无监督学习中的聚类任务**。评价标准不能用“正确率”，因为没有正确答案；通常看同一组内部的相似程度和不同组之间的差异程度。**需要提醒的边界**：分出来的组是数据里的模式，不是天然的类别。某一组叫“爱看小说的人”只是我们给它的名字，如果换一批数据、换一个聚类数量，分组可能会不同。

**问题三：判断一段文字是不是同一篇作文的改写。** 有大量“两段文字”的组合，以及“它们是不是同一篇的改写”这个人工判断。

表述：特征是两段文字的若干可计算指标（长度、共同词语数、句子数量差异等），标签是“是改写”或“不是改写”。这是一个**监督学习中的分类任务**。评价标准可以用精确率（判为改写的里面有多少真的是改写）和召回率（真的改写里有多少被找出来）。**需要提醒的边界**：这个任务涉及对人的判断，如果用于纪律处分，必须有人工复核；而且“改写程度”本身是模糊的概念，标注时不同的人可能给出不同的答案，这类标注不一致会直接影响模型的可靠性。

### 示例二：设计一条规则的失败过程

任务：为“预测学生下学期会不会借科普书”写一条尽量完备的规则，然后找出它的漏洞。

**第一版规则。** 如果这学期借过 3 本以上科普书，就预测会借。**漏洞**：借得多可能是因为老师布置了任务。

**第二版规则。** 如果借过 3 本以上**并且**不是老师布置的，就预测会借。**漏洞**：怎么知道是不是老师布置的？数据里没有这个字段。而且还有一类学生是被同学推荐了某本书才借的。

**第三版规则。** 加上“参加过读书会”这个条件。**漏洞**：参加过读书会的学生里有相当一部分是被要求参加的。

**为什么规则越写越乱。** 每一步修补都针对上一版暴露出的一个具体反例，而每加一个条件，就产生了一批“不满足该条件但其实会借”的新例外。这个过程的本质问题是：**这些条件之间是“和”的关系（都要满足），而现实中影响因素是“或”的关系**——老师布置的、自己感兴趣的、被推荐的，任意一种都可能促成借阅。写规则时需要枚举所有组合，而组合的数量随着特征数迅速增长。

**机器学习怎么处理。** 它不去手工枚举组合，而是让程序从数据里估计“在所有这些条件下，后来真的借了的比例是多少”。程序可以同时考虑多个特征，并给每个特征一个权重，自动找到一个在当前数据上表现较好的组合方式。**需要提醒**：这并不意味着模型“理解”了这些因素——它只是找到了一个在训练数据上拟合得比较好的数值组合。如果新一批学生的行为模式变了，这个组合可能就不再适用。

## 动手实践

**目标**：为三个给定问题分别写出学习任务的表述，并说明各自的类型、评价标准和适用边界。

**材料**：纸和笔，或一个文本文件。不需要写代码。

**步骤**：

1. 抄下下面三个问题。问题甲：根据学生过去一个月的错题记录，预测他下次单元测能不能及格（及格线是 70 分）。问题乙：把全校学生按阅读兴趣分组，分组前不知道有哪些类型。问题丙：根据一段录音，判断说话人是不是本校学生。
2. 对每个问题，写出四行内容：**特征**（能用什么数据描述）、**标签**（有没有、是什么）、**任务类型**（监督/无监督，分类/回归）、**评价标准**（用什么数字判断做得好不好）。
3. 对问题甲和问题丙，各写出**两条可能的失败情况**：什么样的输入会让模型给出错误的结果？比如“新转来的学生没有历史记录”这类。
4. 为问题甲设计一个“不适合用机器学习的理由”并说明在什么情况下成立。例如数据只有 8 个学生时会怎样。
5. 找出一个**不该**用机器学习解决的问题（从你的日常经验里找，比如计算某次考试的平均分），写出理由。
6. 检查你自己在第 2 步写的“评价标准”：如果这个标准在“两类样本数量相差很大”时会失效（比如及格的人占 95%），你能事先发现吗？把发现的隐患写下来。

**完成判据**：三个问题都有完整的四行表述；问题甲和问题丙各有两条具体的失败情况（不是“模型可能出错”这种空话）；第 5 步给出了一个合理的反例；第 6 步能指出至少一个“评价标准在数据不平衡时会误导”的隐患。

**排查方法**：如果你在判断“是分类还是回归”时拿不定主意，依次检查三点。第一，看标签是不是从固定几个类别里选（是分类）还是任意的数值（是回归）。第二，注意一个问题可以有多种提法——预测“期末考几分”是回归，预测“期末考及不及格”就是分类，把连续量切成类别就会改变任务类型。第三，如果你写不出“特征”，说明这个问题可能不是靠现有数据能解决的，应当先确认数据是否可得，而不是急着选模型。

## 常见误区

**误区一：“机器学习就是让电脑自己变聪明。”** 反例：模型不会在任何意义上“变聪明”——它不会积累经验、不会理解内容、不会举一反三。它做的事情是在训练时调整一组数值，使得在这批训练数据上算出的结果尽量接近给定的标签。换一批数据、换一个问题，就要重新训练。把模型说成“学会了”只是习惯上的简略说法，实际含义是“在这批数据上找到了一组拟合较好的参数”。**这个区别在实践上很重要**：以为模型会自己理解，就会在数据质量、分布变化、边界情况上放松警惕。

**误区二：“有数据就能做机器学习。”** 反例：一个班有 8 名转学生，你想预测他们会不会参加读书会。8 个样本几乎不可能支撑任何可靠的预测——数据太少时，你从中学到的模式很可能只是这 8 个人恰好凑出的巧合。更麻烦的是，在小数据上模型往往表现出“完美”的分数（因为它能记住每一个样本），让人误以为效果很好。判断数据是否够用，至少要问：每一条样本是否真的提供了新的信息？标签的数量在不同类别间是否大致均衡？数据是否覆盖了你打算使用模型的那些场景？

**误区三：“模型给出的结果比人的判断更客观，因为它不带偏见。”** 反例：模型完全依赖训练数据，而训练数据里往往带着历史遗留的不平衡。如果过去的记录显示“参加过竞赛的学生更容易被推荐进某个社团”，那么用这些记录训练的模型就会继续倾向于推荐这类学生——它把这个历史模式当成了规律。**模型不会因为“只看数据”就摆脱偏见，恰恰相反，它会把数据里的偏见固化下来，并且因为披着“算法”的外衣而更难被质疑。** 正确的做法是在使用前主动检查：模型在不同群体上的表现是否差别很大（第十、十一章会讲具体方法）。

### Q05 · 实践题

材料：一个合成的小数据集，描述 12 名学生的三项信息：每周自习小时数、参加社团活动次数、是否选过编程入门课；另外记录了他们是否报名参加了程序设计兴趣小组。数据如下（自习小时、社团活动次数、是否选过编程课、是否报名）：

```text
[(5, 1, 1, 1), (8, 0, 1, 1), (2, 3, 0, 0), (6, 2, 0, 1),
 (10, 1, 1, 1), (1, 4, 0, 0), (3, 1, 0, 0), (7, 2, 1, 1),
 (4, 5, 0, 0), (9, 0, 1, 1), (2, 2, 0, 0), (6, 3, 1, 1)]
```

任务：

- 写出这个任务的特征清单和标签，说明属于监督学习还是无监督学习、分类还是回归。
- 手工统计“自习小时数不少于 5”的学生有多少人、其中有多少人报名了，算出这个比例。
- 再统计“选过编程课”的学生有多少人、其中有多少人报名了，算出比例。
- 根据前两步，你认为哪个特征和“报名”的关联更明显？说明你的判断依据。

完成判据：特征和标签写清楚且类型判断正确；两个比例都算对（写出算式）；第 4 步的判断有数字支撑，而不是凭感觉。

### Q06 · 实践题

迁移应用：你要为一个校园活动设计一个“智能推荐”功能，但还没有任何数据。

- 请设计一份数据采集方案：需要记录哪些字段？每条记录代表什么？预期收集多少条才有讨论的价值？
- 明确说明你会先用监督学习还是无监督学习，为什么。
- 至少指出这个方案中**两个**可能出问题的地方（例如数据只来自某一类学生、字段本身不稳定、标签由不同的人标注导致口径不一致），并说明你会怎么检查它们。
- 说明如果你发现数据里缺少某类学生的记录，你会怎么做——注意：**不能通过复制已有记录来凑数**，请说明理由。

## 本章小结

- 机器学习的核心转变是不再由人写规则，而是提供输入与标签的样本，让程序找出一组能从输入算出输出的数值。
- 模型学到的是数据中的统计关联，不是因果机制；这既带来了处理“说不清规则”问题的能力，也带来了被数据中的偶然模式误导的风险。
- 训练数据里有正确答案的是监督学习，按标签是否连续分为分类和回归；没有正确答案、目标是找出数据自身结构的是无监督学习。
- 规则明确、数据不足、数据不能代表使用场景、后果重大不能容错，这四类问题不适合用机器学习解决。
- 下一章会补上必要的数学工具：怎样把数据表示成向量和矩阵，怎样衡量两个样本的接近程度，以及“让误差变小”这句话在数学上是什么意思。
