# 让程序做选择：条件分支

## 学习目标

- 写出包含 if、elif、else 的分支结构
- 用比较和逻辑运算符组合条件
- 处理条件判断的边界情况

## 开始之前

前面几章的程序都是从第一行走到最后一行，一路不拐弯。这一章要让程序学会"看情况"。

先想一想这个问题：你平时判断"要不要带伞"，脑子里是怎么想的？这个判断可以分成哪几步？

材料：一台能运行 Python 的电脑；纸和笔。

## 情景导入

学校要办运动会，按年级分组报名：

```text
初一和初二的同学参加甲组
初三的同学参加乙组
```

小林是初二的学生，他写了个程序来判断自己该报哪一组：

```python
grade = 2
if grade <= 2:
    print("甲组")
else:
    print("乙组")
```

输出是"甲组"，对了。

小雨看了看说："如果有个初一的学生，`grade` 是 1，也输出甲组，没问题。如果以后学校改成只有初一参加甲组呢？"

小林说："那我改一下条件。"

小雨说："那如果分了三个组呢？"

小林想了想，写了个新的：

```python
grade = 2
if grade == 1:
    print("甲组")
elif grade == 2:
    print("乙组")
else:
    print("丙组")
```

老师说："这次对了。但我要提醒你们两个地方。第一，`==` 是两个等号，一个等号是赋值，这个区别很重要。第二，你们要考虑边界：如果有同学跳级或者留级，`grade` 变成了 0 或者 4，程序会输出什么？"

小林试了试，`grade = 4` 的时候输出了"丙组"。他明白了："原来 `else` 是兜底的，所有没被前面条件接住的情况都会掉到这里。"

老师说："对。所以要小心：`else` 会不会接住一些你根本没想到的情况。"

## 知识讲解

### 布尔表达式

条件判断的核心是"判断一件事成立不成立"。这种判断的结果只有两种：成立（`True`）或者不成立（`False`）。这样的表达式叫布尔表达式。

比较运算符有六个：

| 运算符 | 含义 | 例子 | 结果 |
| --- | --- | --- | --- |
| `==` | 等于 | `3 == 3` | `True` |
| `!=` | 不等于 | `3 != 4` | `True` |
| `>` | 大于 | `3 > 4` | `False` |
| `<` | 小于 | `3 < 4` | `True` |
| `>=` | 大于等于 | `3 >= 3` | `True` |
| `<=` | 小于等于 | `3 <= 2` | `False` |

这里最重要的一点：**`=` 和 `==` 是不同的东西**。`=` 是赋值（把值存进变量），`==` 是比较（判断两个值是不是相等）：

```python
score = 60        # 赋值：把 60 存进 score
print(score == 60)   # 比较：判断 score 是不是等于 60
```

输出 `True`。这个混淆是初学者最常见的错误来源，而且它常常不会报错，只会让程序的行为变得奇怪。写条件的时候，先想一想：我这里是要"存一个值"还是"判断是否相等"？

还有一个要注意的地方：比较浮点数时不要直接用 `==`。因为计算机表示小数时有微小的误差，`0.1 + 0.2 == 0.3` 的结果是 `False`，尽管数学上应该相等。要比较两个浮点数是否相等，应该看它们的差是不是足够小：

```python
a = 0.1 + 0.2
b = 0.3
print(abs(a - b) < 0.000001)
```

输出 `True`。

### if 语句

`if` 语句的基本样子是：

```python
if 条件:
    条件成立时执行的语句
```

注意两件事。第一，条件后面要写**冒号**，这是最容易漏的。第二，条件成立时要执行的语句必须**缩进**（一般用 4 个空格）。

缩进在 Python 里不是"为了好看"，而是语法的一部分。它用来标记"哪些语句属于这个条件"。看这个例子：

```python
score = 85
if score >= 60:
    print("及格了")
    print("可以进入下一单元")
print("程序结束")
```

前两个 `print` 缩进了，所以它们属于"条件成立时才执行"；第三个 `print` 没有缩进，所以不管条件成立不成立都会执行。

如果条件不成立时也要做点事，就加 `else`：

```python
score = 45
if score >= 60:
    print("及格了")
else:
    print("还需要再努力")
```

`else` 后面也要写冒号，它下面的语句也要缩进。`else` 不需要写条件，因为它表示"其他所有情况"。

### 多分支和嵌套

情况有三种以上时，用 `elif`（它是 "else if" 的缩写）：

```python
score = 87
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
else:
    grade = "D"
print(grade)
```

输出 `B`。

这里有一个非常重要的机制：**判断是从上到下依次进行的，一旦有一个条件成立，就执行它的语句，然后整个结构就结束了，后面的条件不再检查。**

这个机制带来一个实用的结论：**条件要按从严格到宽松的顺序排列**。看上面这个例子，第二个条件是"大于等于 80"。它能这样写，是因为第一个条件已经接住了所有大于等于 90 的情况，所以走到第二个条件的时候，实际上隐含了"小于 90"这个前提。如果把顺序倒过来写：

```python
score = 95
if score >= 70:
    grade = "C"
elif score >= 80:
    grade = "B"
elif score >= 90:
    grade = "A"
```

95 分满足第一个条件，直接得到"C"，后面的 B 和 A 根本不会被检查。所以顺序错了，结果就完全错了。

`if` 里面还可以再放 `if`，这叫嵌套：

```python
score = 85
attendance = 0.9

if score >= 60:
    if attendance >= 0.8:
        print("通过")
    else:
        print("分数够了，但出勤不足")
else:
    print("分数不足")
```

嵌套的时候缩进会变多，需要注意每一层属于谁。一般嵌套两三层就够，太深了读起来很费劲。

### 逻辑运算符和边界情况

有时候一个条件不够用，需要把几个条件组合起来。三个逻辑运算符：`and`、`or`、`not`。

- `and`：两个都成立才成立
- `or`：有一个成立就成立
- `not`：把成立变成不成立

```python
age = 13
if age >= 12 and age <= 15:
    print("符合初中组年龄")
```

这表示"大于等于 12 并且小于等于 15"。也可以写成 `if 12 <= age <= 15:`，这是 Python 特有的写法，更接近数学上的写法。

`and` 和 `or` 有一个容易忽略的特性叫**短路**：`and` 左边的条件如果已经是不成立，右边的就根本不看；`or` 左边如果已经成立，右边的也不看。这个特性有时会用上，比如判断"列表不为空并且它的第一个元素等于某值"时，先判断不为空可以避免报错。

现在说边界情况。写条件判断时，边界最容易出错，主要有四种。

**第一种：零个怎么办。** 如果条件是"人数超过 0"，而人数是 0，就走不到那一条。要专门想一遍"如果一个都没有"的情况。

**第二种：正好相等怎么办。** 这是最常见的错误。条件是"大于 60"还是"大于等于 60"，60 分本身的结果完全不同。写条件的时候，把边界的那个值拿出来念一遍，看结果是不是你要的。

**第三种：条件互相重叠。** 如果两个 `elif` 的条件有可能同时成立，那实际起作用的只有前面那一个。这时候要检查顺序，或者把条件改得更明确。

**第四种：`else` 太宽。** `else` 会接住所有没被前面接住的情况，包括你根本没想到的。比如前面算年龄分组的例子，如果 `score` 是负数，它也会掉进 `else` 里，给出一个看起来正常的答案。稳妥的做法是在最前面加一个检查，专门处理明显不合理的输入。

## 详细示例

### 示例一：根据多个条件判断奖学金等级

**问题**：某校的奖学金评定规则是：学期总评达到 90 分且没有任何缺勤，评为一等奖；总评达到 85 分且缺勤不超过 2 次，评为二等奖；总评达到 80 分，评为三等奖；其余情况不评。请写一个程序判断某个学生能评几等奖。

**材料**：Python 环境；纸和笔。

**逐步推理**：

第一步，明确需要哪些数据。需要两个：学期总评分数、缺勤次数。

```python
total = 92
absences = 0
```

第二步，把规则翻译成条件，注意顺序要从严格到宽松。一等奖的条件最严格（分数 90 以上还要零缺勤），所以放最前面：

```python
if total >= 90 and absences == 0:
    result = "一等奖"
elif total >= 85 and absences <= 2:
    result = "二等奖"
elif total >= 80:
    result = "三等奖"
else:
    result = "不评"
```

第三步，用手头的例子走一遍。`total` 是 92，`absences` 是 0。第一个条件：92 大于等于 90 成立，0 等于 0 也成立，两个都成立，所以结果是"一等奖"。

第四步，测试其他情况。把数据改一改，逐个验证：

- `total = 92, absences = 1`：第一个条件中缺勤不满足，走到第二个条件，92 大于等于 85 成立，1 小于等于 2 成立，得到"二等奖"。合理吗？按照规则，一等奖要求零缺勤，所以缺勤一次只能拿二等奖，正确。
- `total = 86, absences = 5`：第一个不成立（分数不够），第二个也不成立（缺勤超过 2），第三个成立（86 大于等于 80），得到"三等奖"。合理吗？规则写的是"总评达到 80 分，评为三等奖"，没有附加缺勤条件，所以正确。但这个结果值得注意：缺勤 5 次的学生和缺勤 0 次的学生都是三等奖，这是规则本身的规定。
- `total = 75`：三个条件都不成立，落到 `else`，得到"不评"。

第五步，检查边界。这是最重要的一步。

- `total = 90, absences = 0`：第一个条件成立（90 大于等于 90），得到一等奖。这正是"大于等于"的含义。
- `total = 90, absences = 1`：第一个不成立，第二个成立（90 大于等于 85），得到二等奖。
- `total = 85, absences = 2`：第二个条件成立，得到二等奖。
- `total = 85, absences = 3`：第二个不成立，第三个成立（85 大于等于 80），得到三等奖。
- `total = 80`：第三个成立，得到三等奖。
- `total = 79.5`：三个都不成立，得到"不评"。

第六步，把完整程序写出来，加上输出：

```python
total = 92
absences = 0

if total >= 90 and absences == 0:
    result = "一等奖"
elif total >= 85 and absences <= 2:
    result = "二等奖"
elif total >= 80:
    result = "三等奖"
else:
    result = "不评"

print(f"总评 {total}，缺勤 {absences} 次，评定结果：{result}")
```

输出：`总评 92，缺勤 0 次，评定结果：一等奖`。

**结果**：程序正确实现了四档评定，并通过了边界测试。

**为什么正确**：我们把规则里的每一条都翻译成了一个条件，并且按照"从严格到宽松"的顺序排列。这样做是必要的，因为判断是依次进行的，一旦成立后面的就不再检查。如果把"总评达到 80"这条放到最前面，那么 92 分的学生也会被评成三等奖，因为 92 也满足"大于等于 80"。

**一个边界情况**：如果 `absences` 是负数（比如录入数据时打错了）呢？按现有程序，`total = 92, absences = -1` 会得到一等奖，因为 -1 确实"等于 0"不成立，但等一下——`absences == 0` 对 -1 来说是不成立的，所以第一个条件不满足，会走到第二个条件，得到二等奖。这个结果虽然没有崩溃，但显然不合理：缺勤次数不可能为负数。这说明**程序不会自动发现不合理的输入**，它只会按条件机械地判断。稳妥的做法是在最前面加一道检查：

```python
if total < 0 or total > 100 or absences < 0:
    print("输入数据有问题，请检查")
elif ...
```

这个习惯在处理任何用户输入时都值得养成。

### 示例二：修好一段条件顺序错误的程序

**问题**：小北写了一个判断火车票种类的程序。规则是：6 岁以下免票，6 到 14 岁半价，14 岁以上全价。他写成了下面这样，请找出问题并修正。

```python
age = 5

if age >= 6:
    price_type = "半价"
elif age < 6:
    price_type = "免票"
else:
    price_type = "全价"

print(price_type)
```

**材料**：上面的代码；Python 环境。

**逐步推理**：

第一步，逐个测试。先算 `age = 5`：第一个条件 5 大于等于 6 不成立；第二个条件 5 小于 6 成立，得到"免票"。结果正确。

第二步，测试 `age = 10`：第一个条件成立，得到"半价"。正确。

第三步，测试 `age = 20`：第一个条件 20 大于等于 6 成立！所以得到"半价"。但按照规则，20 岁应该是全价。**发现错误。**

第四步，分析原因。规则里有三档：免票、半价、全价。但小北的条件只覆盖了两种情况：`age >= 6` 和 `age < 6`。这两个条件合起来已经覆盖了所有可能的年龄（任何数要么大于等于 6，要么小于 6），所以第三个 `else` 永远走不到——它成了"死代码"。

第五步，认识到问题的本质：**`age >= 6` 这个条件太宽了**。它想表达的是"6 到 14 岁"，但写成 `>= 6` 就包括了 14 岁以上的所有人。

第六步，修正。把条件写准确，并且按从大到小或者从小到大排列，确保每一段的范围是明确的：

```python
age = 20

if age < 6:
    price_type = "免票"
elif age <= 14:
    price_type = "半价"
else:
    price_type = "全价"

print(price_type)
```

第七步，重新测试所有情况：

- `age = 5`：5 小于 6 成立，得到"免票"。
- `age = 6`：5 小于 6 不成立；6 小于等于 14 成立，得到"半价"。符合规则（"6 到 14 岁半价"包含 6 岁）。
- `age = 14`：14 小于等于 14 成立，得到"半价"。符合规则。
- `age = 15`：两个条件都不成立，落到 `else`，得到"全价"。符合规则。
- `age = 20`：得到"全价"，正确。

第八步，特别注意第二个条件的写法。它写的是 `age <= 14`，而不是 `6 <= age <= 14`。这是可以的，因为走到这一句的时候，`age < 6` 已经被排除了，所以隐含了"大于等于 6"这个前提。这种写法的好处是简短，坏处是不太直观——读代码的人需要自己推理。如果要写得更清楚，可以写完整的 `elif 6 <= age <= 14:`，效果完全一样。

**结果**：原程序的问题是第一个条件 `age >= 6` 覆盖范围太大，导致 14 岁以上也被判为"半价"。修正后把条件改为先判断 `age < 6`，再判断 `age <= 14`，其余走 `else`。修正后的程序通过了全部边界测试。

**为什么正确**：我们用"逐个测试边界值"的办法发现了问题——正是因为测了 20 岁这个明显超出范围的值，才暴露出条件覆盖不完整。这也说明一个重要的习惯：**写完条件判断以后，要把每个分界点上的值都测一遍**，包括分界点本身、分界点减一、分界点加一。

**一个边界情况**：如果年龄是 5.5 岁呢？`5.5 < 6` 成立，得到"免票"。这符合规则（6 岁以下）。但如果年龄是 14.5 呢？`14.5 <= 14` 不成立，落到 `else`，得到"全价"。这也是合理的，因为 14.5 岁已经超过 14 岁了。这说明条件用的是小于还是小于等于，直接影响 14 岁和 14.5 岁的判断。所以规则写成"6 到 14 岁"的时候，必须和出题的人确认清楚：14 岁整和 14 岁零几个月怎么算。**这种含糊的地方正是程序出错的高发区。**

## 动手实践

**目标**：写一个包含多层条件判断的程序，并用边界测试验证它的正确性。

**材料**：一台能运行 Python 的电脑；纸和笔。

**步骤**：

1. 先设计一个判断规则。建议从这些里选：根据 BMI 判断体重是否正常（需要身高体重）；根据成绩判断等级；根据消费金额判断折扣比例；根据时间段判断该说"早上好"还是"晚上好"。
2. 把规则写在纸上，写成表格形式：每一档的条件是什么、结果是什么。至少要有三档。
3. 检查规则有没有遗漏的情况。特别是问自己：如果数据是 0 会怎样？如果是负数？如果超过最大值？
4. 在程序里把规则写成 `if` / `elif` / `else` 结构。注意条件要从严格到宽松排列。
5. 现在做边界测试。在纸上列出所有分界点的值，每个分界点写三个数：分界值本身、它减一点点、它加一点点。把它们列成一张表。
6. 对表格里的每一个值，先在纸上写出你预期的结果（这一步不能省）。
7. 在程序里逐个把这些值代入运行，把实际结果和你的预期对照，填在表格的最后一列。
8. 找出不一致的地方。如果有，先判断是你的预期错了还是程序错了，然后修改。
9. 故意加一个"坏数据"测试：代入一个明显不合理的值（比如负年龄），看看程序会输出什么。如果你的程序给出了一个看起来正常的答案，说明需要加一道输入检查。
10. 最后把程序整理一遍，加上注释说明每一档的条件。

**完成判据**：程序至少有三档判断；纸上有一张边界测试表，每个分界点都测了三个值（分界值、减一点、加一点）；表格里的预期和实际结果都填了；至少发现并处理了一个边界问题，或者能说明为什么你的分界值不会出问题；第 9 步做过了，并且你能说出对于不合理输入，你的程序会怎么反应。

**排查方法**：

- 如果所有测试都得到同一个结果，检查是不是第一个条件写得太宽，把所有情况都接住了。
- 如果漏掉了某些情况的处理，程序可能返回 `None` 或者报错，这时要检查有没有 `else` 兜底。
- 如果边界上的结果和预期不一致，检查你用的是 `>` 还是 `>=`。这两个差一个值。
- 如果缩进报错，检查每一行的缩进是不是一致的四个空格，不要混用制表符和空格。
- 如果条件太长读不懂，把它拆成几个变量，比如先把判断结果存成 `is_pass = score >= 60`，条件里用 `is_pass`。

## 常见误区

### 误区一："一个等号和两个等号差不多"

**错误说法**：`if score = 60:` 和 `if score == 60:` 是一个意思。

**为什么错**：一个等号是赋值，两个等号是比较。`if score = 60:` 会直接报语法错误，因为 `if` 后面需要的是一个条件（能判断真假的东西），而赋值语句不是条件。但如果是在别的地方弄混，可能不报错却出问题。养成习惯：赋值用 `=`，判断相等用 `==`。

**正确理解**：读代码时把 `=` 读成"存进去"，把 `==` 读成"是不是相等"。这两个动作完全不同。

### 误区二："条件的顺序可以随便换"

**错误说法**：反正每个条件都会检查一遍，先写哪个都一样。

**为什么错**：判断是从上往下依次进行的，一旦有一个成立，后面的就不再检查了。所以顺序直接决定结果。前面火车票的例子就是这样：`age >= 6` 写在最前面，把 20 岁的情况也接住了，后面给 14 岁以上准备的 `else` 永远走不到。

**正确理解**：条件要按从严格到宽松的顺序排列。最特殊、要求最多的条件放前面，最宽泛的放最后。写完以后想一遍：每个条件放在这个位置，它实际会接住哪些值？

### 误区三："else 能接住所有想不到的情况"

**错误说法**：有 `else` 兜底就安全了，所有情况都会被处理。

**为什么错**：`else` 确实会接住所有没被前面接住的情况，但这也意味着**它会悄悄地接住你根本没想到的情况**。比如年龄分组的程序，如果录入了一个负数年龄，`else` 会给出一个看起来正常的答案，你不会发现数据有问题。这种"静默地接受了错误数据"的行为比报错更危险。

**正确理解**：`else` 是兜底但不是保险。稳妥的做法是在最前面加一道输入检查，把明显不合理的值先挑出来。写程序时多问一句："如果输入是我完全没想到的东西，会发生什么？"

## 本章小结

- 布尔表达式的结果只有 `True` 和 `False`；比较用 `==`、`!=`、`>`、`<`、`>=`、`<=`，注意 `==` 和 `=` 是两回事。
- `if` 后面要有冒号，条件成立时要执行的语句必须缩进；缩进在 Python 里是语法的一部分。
- `elif` 用于处理三种以上的情况；判断从上到下依次进行，一旦成立后面的就不再检查，所以条件要从严格到宽松排列。
- `and`、`or`、`not` 用来组合条件，它们有短路特性。
- 边界情况最容易出错：零个、正好相等、条件重叠、`else` 接住没想到的情况；写完要把每个分界点都测一遍。
