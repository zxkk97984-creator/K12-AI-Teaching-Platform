## 知识讲解

### 第一步：需求分析

做任何程序的第一步都不是写代码，而是把"要做什么"想清楚。可以问四个问题。

**要处理什么数据？** 这个项目里是"每个学生的姓名和若干门课的成绩"。

**数据从哪来？** 从文件读进来（文件格式要先定好）。

**要算出什么？** 需要三类结果：一是班级整体的（平均分、最高分、最低分）；二是每个学生个人的（总分、平均分、名次）；三是按科目的（每门课的平均分，找出最差的几门）。

**结果怎么输出？** 输出到屏幕，也可以同时写进文件。

把这四个问题写在纸上，就是一份完整的"需求清单"。为什么要写下来？因为**写代码的时候容易跑偏**——写着写着去处理一个没人要求的细节，却漏掉了一个重要需求。对照清单就不会漏。

### 第二步：设计数据结构

数据结构就是"数据怎么组织"。这一步的选择会直接影响后面代码好不好写。

考虑这个项目的需要。对每个学生，我们要记录姓名和几门课的成绩。成绩是"科目到分数"的对应，所以用字典；学生本身有姓名和成绩，也是一个字典；所有学生组成一个列表。

```python
students = [
    {"姓名": "小雨", "成绩": {"语文": 88, "数学": 95, "英语": 79}},
    {"姓名": "小北", "成绩": {"语文": 92, "数学": 78, "英语": 85}},
]
```

这就是"列表套字典，字典里再套字典"的结构。看起来有点复杂，但它正好对应了数据的真实形状：一群人，每人有名字和一份成绩单，成绩单上是科目和分数。

为什么不用"两个列表"（一个存名字，一个存分数）？因为那样容易错位——你删掉名字列表里的第三项，忘了删分数列表里的第三项，后面全部对不上了。用嵌套结构就不会有这个问题，因为每个学生的所有信息都在一起。

一个实用的建议：**先用一两行假数据把结构写出来，打印看看，确认符合你的想象，再开始写处理逻辑**。

### 第三步：分步实现

不要一次把所有功能都写完。按"能跑通"的顺序一步一步来，每做完一步就测试。

一个合理的实现顺序是：

1. 准备一份小的测试数据（不要用真实的四十条，先用三条）。
2. 实现"从文件读数据"，读进来以后打印看看对不对。
3. 实现"算每个学生的总分和平均分"，打印看看。
4. 实现"算班级的平均分、最高分、最低分"。
5. 实现"排名次"。
6. 实现"按科目统计"。
7. 换成真实的大数据，检查速度。
8. 加上异常处理，处理文件缺失、格式不对等情况。

这个顺序的特点是：**每一步都基于上一步已经验证过的结果**。如果第 5 步出了问题，你知道前四步是好的，只需要看第 5 步。

### 第四步：测试与异常处理

程序写完了不等于做好了，还要测试。

**正常情况测试。** 用你准备好的数据跑一遍，把每个输出都和手算的结果对照。

**边界测试。** 至少想到这几种：

- 数据文件不存在。
- 数据文件是空的（只有表头，没有数据）。
- 某一行缺字段。
- 某个分数栏里写了文字。
- 某个分数是 0 或者满分。
- 只有一个人。

**结果合理性测试。** 算完以后问自己几个问题：名次有没有连续？最高分和最低分有没有搞反？平均分有没有落在最高分和最低分之间？这些"看起来像常识"的检查，常常能发现隐藏的问题。

异常处理的原则是：**能继续的就跳过并报告，不能继续的就明确告知**。比如一行数据坏了，可以跳过并在最后报告"跳过了 2 行"；如果整个文件都读不到，就没法继续，应该清楚地告诉使用者。

有一件事要特别注意：**不要静默地跳过坏数据**。如果跳过了却不告诉使用者，他会以为结果包含了全部数据，得出错误的结论。所以跳过多少条、哪几条被跳过，都应该说出来。

### 第五步：回顾和改进

程序能跑以后，回头看一遍，问自己几个问题。

**代码有没有重复？** 如果同一段逻辑出现了两次以上，就该做成函数。

**名字够不够清楚？** `data`、`temp`、`x` 这样的名字，过一周你自己也看不懂。

**有没有考虑到的边界没处理？** 再想一遍"如果输入是我完全没想到的东西，会怎样"。

**效率够不够？** 如果数据量会变得很大（比如整个年级），现在的算法还行吗？比如每算一个学生的名次都遍历一遍全体，那是"人数乘人数"的次数；数据多了会变慢。

这几个问题不需要都解决，但要想一遍。**能说清楚"我的程序在什么情况下会变慢""哪些情况我还没处理"，本身就是能力。**

## 详细示例

### 示例一：完整实现成绩分析器

**问题**：请实现一个班级成绩分析器。数据文件是 CSV 格式，第一行是表头"姓名,语文,数学,英语"，后面每行是一个学生的数据。程序要输出班级统计、每个学生的排名、以及各科的平均分。

**材料**：Python 环境；纸和笔；用来测试的 CSV 文件。

**逐步推理**：

第一步，先准备测试数据，写在纸上：

```text
姓名,语文,数学,英语
小雨,88,95,79
小北,92,78,85
小然,75,88,60
```

第二步，手工算出所有需要的结果，作为核对依据。

每人的总分：小雨 88 + 95 + 79 = 262；小北 92 + 78 + 85 = 255；小然 75 + 88 + 60 = 223。

每人的平均分：小雨 262 / 3 ≈ 87.33；小北 255 / 3 = 85.00；小然 223 / 3 ≈ 74.33。

班级总分（所有学生所有科目的和）：262 + 255 + 223 = 740。全体平均分：740 / 9 ≈ 82.22。

最高总分 262，最低总分 223。

名次（按总分从高到低）：第 1 名小雨（262）、第 2 名小北（255）、第 3 名小然（223）。

各科平均分：语文 (88 + 92 + 75) / 3 = 255 / 3 = 85.0；数学 (95 + 78 + 88) / 3 = 261 / 3 = 87.0；英语 (79 + 85 + 60) / 3 = 224 / 3 ≈ 74.67。

第三步，设计数据结构。读进来以后，每个学生是一个字典：

```python
{"姓名": "小雨", "成绩": {"语文": 88, "数学": 95, "英语": 79}}
```

第四步，写读取函数：

```python
import csv

def load_students(path):
    """读取成绩文件，返回学生列表。出错时返回空列表并给出提示。"""
    students = []
    try:
        with open(path, encoding="utf-8") as f:
            reader = csv.DictReader(f)
            for row in reader:
                name = (row.get("姓名") or "").strip()
                if not name:
                    continue
                scores = {}
                for subject in ("语文", "数学", "英语"):
                    try:
                        scores[subject] = int(row[subject])
                    except (KeyError, TypeError, ValueError):
                        pass
                if scores:
                    students.append({"姓名": name, "成绩": scores})
    except FileNotFoundError:
        print(f"找不到文件：{path}")
    return students
```

这里处理了三种异常：`KeyError`（缺少这一列）、`TypeError`（值是 `None`）、`ValueError`（值不是数字）。任何一种情况下，这一科就被跳过，但学生仍然保留他其他的科目。

第五步，写计算函数。先是单人统计：

```python
def student_total(student):
    return sum(student["成绩"].values())

def student_average(student):
    scores = student["成绩"]
    if not scores:
        return 0
    return sum(scores.values()) / len(scores)
```

第六步，写班级统计：

```python
def class_stats(students):
    if not students:
        return None
    totals = [student_total(s) for s in students]
    all_scores = [v for s in students for v in s["成绩"].values()]
    return {
        "人数": len(students),
        "班级平均分": sum(all_scores) / len(all_scores),
        "最高总分": max(totals),
        "最低总分": min(totals),
    }
```

注意 `all_scores` 用了嵌套的列表推导——外层遍历学生，内层遍历他的成绩。这样一次就把所有人的所有分数收集起来了。

第七步，写排名：

```python
def rank_students(students):
    ranked = sorted(students, key=student_total, reverse=True)
    result = []
    for i, s in enumerate(ranked, start=1):
        result.append({
            "名次": i,
            "姓名": s["姓名"],
            "总分": student_total(s),
            "平均分": student_average(s),
        })
    return result
```

`key=student_total` 直接传函数名，表示"用这个函数算出来的值来排序"。这比写 `lambda` 更清楚。

第八步，写科目统计：

```python
def subject_stats(students):
    subjects = set()
    for s in students:
        subjects.update(s["成绩"].keys())

    result = {}
    for subject in subjects:
        values = [s["成绩"][subject] for s in students if subject in s["成绩"]]
        if values:
            result[subject] = sum(values) / len(values)
    return result
```

第九步，写主程序把所有部分连起来：

```python
def main():
    students = load_students("scores.csv")
    if not students:
        print("没有读到数据，请检查文件")
        return

    stats = class_stats(students)
    print(f"班级人数：{stats['人数']}")
    print(f"班级平均分：{stats['班级平均分']:.2f}")
    print(f"最高总分：{stats['最高总分']}")
    print(f"最低总分：{stats['最低总分']}")

    print("\n名次表：")
    for row in rank_students(students):
        print(f"第 {row['名次']} 名：{row['姓名']}，"
              f"总分 {row['总分']}，平均 {row['平均分']:.2f}")

    print("\n各科平均分：")
    for subject, avg in subject_stats(students).items():
        print(f"{subject}：{avg:.2f}")

main()
```

第十步，运行，和第二步的手算结果逐项对照。

班级人数 3。班级平均分 82.22。最高总分 262，最低总分 223。

名次表：小雨第 1（262，87.33）、小北第 2（255，85.00）、小然第 3（223，74.33）。

各科平均分：语文 85.00、数学 87.00、英语 74.67。

全部与手算一致。

**结果**：程序完整输出了四类结果，全部与手工计算一致。

**为什么正确**：我们把程序拆成了五个函数，每个函数只负责一件事：读数据、算单人统计、算班级统计、算排名、算科目统计。这样做的好处是每一部分都可以单独测试——比如你怀疑排名不对，只需要测 `rank_students`，不用管读文件的部分。

**一个边界情况**：如果某个学生只有 2 门课的成绩（第三门缺了）呢？`student_total` 会得到那两门的和，`student_average` 会除以 2，所以他的平均分是基于两门课算的，和其他人的三门课平均分**不可比**。但程序不会报错，也不会提示。这是一个很隐蔽的问题：**名次看起来正常，实际上是在比较不同的东西**。

处理办法有两种。一是要求数据必须完整，缺科目的学生单独列出来提醒；二是在输出里标出每个学生的有效科目数，让看的人知道。无论选哪种，关键是**不要让它静默地发生**。可以在 `load_students` 里记录缺科目的情况，最后统一报告。

### 示例二：为程序设计测试用例

**问题**：上面的程序写好了。请设计一套测试用例，覆盖正常情况和各种异常，并说明每种情况预期会发生什么。

**材料**：Python 环境；几个不同内容的测试文件。

**逐步推理**：

第一步，列出要测的情况。从"输入可能长什么样"这个角度想：

| 编号 | 测试情况 | 预期结果 |
| --- | --- | --- |
| 1 | 三条正常的完整数据 | 输出正确的统计和排名 |
| 2 | 文件不存在 | 输出"找不到文件"，不崩溃 |
| 3 | 只有表头，没有数据 | 输出"没有读到数据"，不崩溃 |
| 4 | 某行只有一个分数 | 该学生只统计这一科，不崩溃 |
| 5 | 某分数是 "abc" | 跳过该科目，不崩溃 |
| 6 | 只有一条数据 | 名次只有第 1 名，最高等于最低 |
| 7 | 分数是 0 | 正常统计，0 分是合法成绩 |
| 8 | 姓名是空白 | 跳过这一行 |
| 9 | 所有分数都一样 | 名次按原有顺序排，平均分等于那个分数 |

第二步，针对每一种情况准备测试文件。可以直接写几个小的 CSV 文件，用不同的名字。

第三步，逐个运行，把实际结果和预期对照，填在表格里。

第四步，重点看第 6 种情况。只有一个人时，`max` 和 `min` 得到的是同一个数，程序不会报错。这算正确吗？从"统计"的角度说是正确的，但一个只有一人的"排名"意义不大。这不是程序错误，而是程序正常处理了一个不常见的情况。

第五步，重点看第 9 种情况。所有分数相同时，`sorted` 会保持原有顺序，所以名次是按在文件里出现的顺序排的。这是合理的，但应该知道这一点——如果有人问"分数一样为什么他排前面"，答案就是"按原始顺序"。

第六步，做一个"数据完整性"测试。手工往文件里加两行坏数据（一行分数是字母，一行缺少一列），运行，观察程序是否报告了跳过的情况。如果程序默默跳过而不提示，就需要改进——加上统计和提示。

第七步，检查结果合理性。对正常数据的那次运行，验证三条"常识检查"：

- 平均分是否落在最低分和最高分之间？（82.22 在 60 和 95 之间，是）
- 名次是否从 1 连续到人数？（1、2、3，是）
- 各科平均分的平均值，是否等于班级平均分？语文 85、数学 87、英语 74.67，三个的平均是 82.22，与班级平均分一致。这个检查很有用，因为它从两个不同的角度算了同一个量。

**结果**：得到一张 9 行的测试用例表，其中第 6 到第 9 种情况揭示了需要额外说明或改进的地方（数据不完整、分数相同、全部相等等）。

**为什么正确**：我们用的办法是"先把可能遇到的情况列全，再逐个验证"。这样能发现只测正常数据时看不到的问题。特别是"结果合理性检查"这几条，它们不依赖具体数据的正确值，而是检查结果之间的一致性，可以发现很多隐藏的错误。

**一个边界情况**：如果测试发现第 4 种情况（某行缺一个科目）会导致统计结果不可比，但改起来很麻烦怎么办？一个可行的折中办法是：程序照常计算，但在输出时把"科目数不足"的学生单独列出来提醒。这样既不改动核心逻辑，又不会让使用者被误导。**"提醒"往往比"禁止"更实用**——因为实际数据总是有不完美的，程序不能因为一处不完美就完全罢工。

## 动手实践

**目标**：独立完成一个数据分析和报告程序，并做完整的测试。

**材料**：一台能运行 Python 的电脑；纸和笔；CSV 文件。

**步骤**：

1. 先做需求分析。在纸上回答四个问题：要处理什么数据、数据从哪来、要算出什么、结果怎么输出。至少列出四项要输出的结果。
2. 设计数据结构，把它写在纸上。如果是两级结构，画个示意图说明每一层是什么。
3. 准备测试数据。手工编至少 4 条记录，写在纸上，并且把每一项要统计的结果都手工算出来。
4. 把测试数据保存成一个 CSV 文件。
5. 实现"读数据"这一部分，读进来以后打印出来看看。确认结构和你设计的一致。
6. 实现第一个统计功能（比如算每个人的总分），输出结果，和第 3 步的手算对照。
7. 实现第二个功能（比如排名），对照手算。
8. 实现第三个功能（比如按类别统计），对照手算。
9. 把各部分整理成函数。检查有没有重复的代码——如果有，把它提取成函数。
10. 现在做异常测试。依次构造这四种情况并运行：文件不存在；文件只有表头；某行缺字段；某行的数字栏是字母。每一种都记下程序的反应。
11. 针对第 10 步中发现的问题，加上异常处理。要求：能继续的跳过并**报告跳过了多少**，不能继续的给出明确提示。
12. 做结果合理性检查，验证三条：平均值在最小值和最大值之间；名次从 1 连续到人数；从两个不同角度算出的同一个量是否一致。
13. 最后写一段简短说明，写清楚：你的程序能处理什么、不能处理什么、在什么情况下会出错。

**完成判据**：四项以上输出结果都实现了且与手算一致；代码里没有重复的逻辑（重复的都做成了函数）；第 10 步的四种异常全部测试过并记录；第 11 步的异常处理生效且会报告跳过数量；第 12 步的三条合理性检查都做了；第 13 步的说明写清楚了程序和它的局限。

**排查方法**：

- 如果读进来的数据和你的设计不符，先打印一条记录看看结构。不要急着改处理逻辑，先确认读对了。
- 如果统计结果和手算不一致，先核对数据本身——是不是某条数据录入错了。然后在关键位置打印中间值。
- 如果程序在处理坏的输入时崩了，检查异常处理的类型是不是覆盖到了。可以先用 `except Exception as e: print(type(e), e)` 把错误类型打出来。
- 如果输出太乱看不清，把中间调试的打印删掉，或者注释起来。
- 如果代码开始变得很长不好改，检查是不是有函数做得太多了。一个函数只做一件事。

## 常见误区

### 误区一："先把功能都写完再测试"

**错误说法**：一次写完所有功能，最后一起测，省得来回跑。

**为什么错**：功能多的时候，最后一起测试发现有问题，你很难判断是哪一部分造成的。而且如果第一部分的错误导致数据结构不对，后面所有的功能都会出错，你要找的问题就变成了一大堆。分步实现、每步测试，看起来慢，实际快得多——因为每一步的问题范围都很小。

**正确理解**：按"能跑通"的顺序一步步实现，每做完一步就验证。这样任何时候出错，你都知道问题在刚刚写的那一部分。

### 误区二："跳过坏数据就可以了，不用告诉使用者"

**错误说法**：遇到格式不对的行就跳过，程序能跑完就行。

**为什么错**：跳过之后，统计结果的分母变了，结果的含义也跟着变了。如果使用者不知道有三行被跳过，他会以为这个结果代表了全部数据，从而得出错误的结论。比如平均分本来是全班四十人的，跳过了五个人的数据，就成了三十五个人的平均分——这两个数字不能互相比较。

**正确理解**：跳过可以，但必须报告跳过了多少、跳过了哪些。**"能继续处理"和"如实告知处理了什么"是两件事，两件都要做**。

### 误区三："程序跑通了就是做好了"

**错误说法**：能输出结果，这个项目就算完成了。

**为什么错**：跑通只说明它在**你准备的那一份数据**上能工作。真实数据会包含各种你在测试时没想到的情况。另外，跑通也不代表结果正确——逻辑错误不会报错，你需要用"合理性检查"来判断。

**正确理解**：跑通是第一步，测试和检查是第二步。至少要问自己：边界情况想过了吗？结果合理吗？出错了会怎样？把这些都能说清楚，才算做好。

## 本章小结

- 做程序的第一步是需求分析：要处理什么数据、数据从哪来、要算出什么、结果怎么输出。
- 数据结构的选择直接影响代码好不好写；嵌套结构（列表套字典）适合"每个对象有多个属性，某个属性又是一组数据"的情况。
- 分步实现，每步测试；这样出错时问题的范围很小，容易定位。
- 测试要覆盖正常情况和边界情况；跳过坏数据必须报告跳过了多少，否则会误导使用者。
- 结果合理性检查很有用：平均值应在最值之间、名次应连续、从不同角度算同一个量应该一致。

这本书到这里就结束了。我们从"写出第一个程序"开始，一路学到了变量、字符串、条件、循环、列表、字典、函数、文件、调试，最后做出了一个完整的项目。这些内容在下一本《从数据到人工智能》里会继续用到——因为数据分析本质上就是"用程序处理一批数据"，而这正是你这本书学的东西。
