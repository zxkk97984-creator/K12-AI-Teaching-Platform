# 评估模型的好坏

## 学习目标

- 用混淆矩阵计算准确率、精确率与召回率
- 说明只看准确率会漏掉什么
- 根据任务目标选择合适的指标

## 开始之前

上一章我们学会了做预测。这一章要回答一个更难的问题：怎么判断一个模型好不好？

先想一想这个问题：如果一个模型要判断"这封邮件是不是垃圾邮件"，而它把所有邮件都判成"不是垃圾邮件"，它的准确率是多少？这个模型有用吗？

材料：一台能运行 Python 的电脑；一支笔、一本练习本。

## 情景导入

小雨的模型做好了。她在一份测试数据上测了一下，准确率 90%。

老师说："这个数字听起来不错。但我有一个问题：你的数据里，两类各占多少？"

小雨查了查说："一类有 90 个，另一类有 10 个。"

老师说："那你这个 90% 说明不了什么。"

小雨不解："为什么？"

老师说："你可以试一下：让程序永远输出'大多数那一类'，看看准确率是多少。"

小雨改了改程序，让它不管输入什么都输出第一类。结果准确率还是 90%。

小雨说："怎么会？"

老师说："因为你的数据里第一类占了 90%，所以无脑判成第一类就能对 90%。你的模型准确率和'什么都不学'是一样的。"

小雨说："那我该怎么评估？"

老师说："你需要能看出'它到底有没有真的分辨出第二类'的指标。这就是今天要讲的混淆矩阵、精确率和召回率。"

## 知识讲解

### 混淆矩阵

要细致地评估一个二分类模型，先要看清它"错在哪里"。办法是把预测结果分成四种情况。

|  | 实际是正类 | 实际是负类 |
| --- | --- | --- |
| 预测为正类 | 真阳性 TP | 假阳性 FP |
| 预测为负类 | 假阴性 FN | 真阴性 TN |

这四个缩写来自英文：TP 是"真的、判为正"，FP 是"假的、判为正"，FN 是"假的、判为负"，TN 是"真的、判为负"。

用具体的例子理解。假设任务是"判断这封邮件是垃圾邮件"，正类就是"垃圾邮件"。

- **TP（真阳性）**：邮件确实是垃圾邮件，模型也判成了垃圾邮件。判对了。
- **FP（假阳性）**：邮件是正常邮件，模型却判成了垃圾邮件。**误报了**——把好东西当成坏的。
- **FN（假阴性）**：邮件是垃圾邮件，模型却判成了正常邮件。**漏报了**——把坏东西放过去了。
- **TN（真阴性）**：邮件是正常邮件，模型也判成了正常邮件。判对了。

把这个四种情况的数量数出来，填进表格，就叫混淆矩阵。它是后面所有指标的基础。

```python
def confusion_matrix(true_labels, predicted, positive="是"):
    tp = fp = fn = tn = 0
    for t, p in zip(true_labels, predicted):
        if t == positive and p == positive:
            tp += 1
        elif t != positive and p == positive:
            fp += 1
        elif t == positive and p != positive:
            fn += 1
        else:
            tn += 1
    return tp, fp, fn, tn
```

这里要注意：**"正类"是哪一个是你自己定义的**。通常我们把"我们想找出来的那一类"定义成正类。找垃圾邮件时正类是垃圾邮件；找患病的人时正类是生病的人。定义不同，后面所有指标的数值都会变，所以报告里必须写清楚正类是哪个。

### 准确率及其局限

**准确率**是判对的占全部的多少：

$$\text{准确率} = \frac{TP + TN}{TP + FP + FN + TN}$$

它很直观，但在**类别不平衡**的时候会严重误导。

用一个具体的数字说明。假设 100 封邮件里有 9 封垃圾邮件。

- 情况一：模型很聪明，找出了 8 封垃圾邮件，但也误判了 5 封正常邮件。混淆矩阵是 TP=8、FP=5、FN=1、TN=86。准确率是 (8 + 86) / 100 = 94%。
- 情况二：模型什么都不学，全部判成"正常邮件"。混淆矩阵是 TP=0、FP=0、FN=9、TN=91。准确率是 (0 + 91) / 100 = 91%。

**惰性模型的准确率是 91%，只比聪明模型低 3 个百分点。** 但从实用角度看，两者天差地别：一个真的找出了垃圾邮件，一个什么都没做。

这就是准确率的局限：**当两个类别数量相差很大时，多数类会主导这个指标**。只要把所有的都判成多数类，就能得到一个看起来不错的准确率。

所以看到"准确率 90%"这句话，第一件事应该是问：**数据里的两类各占多少？** 如果本来就是 9:1，那 90% 等于什么都没学到。

### 精确率和召回率

要解决上面的问题，需要把"误报"和"漏报"分开来看。

**精确率**衡量的是"模型说是正类的那些，有多少真的是正类"：

$$\text{精确率} = \frac{TP}{TP + FP}$$

用情况一的数据：8 / (8 + 5) = 8/13 ≈ 0.615。意思是模型判为垃圾邮件的 13 封里，只有 8 封是真垃圾邮件，另外 5 封是误报。

**召回率**衡量的是"所有真正的正类里，模型找出了多少"：

$$\text{召回率} = \frac{TP}{TP + FN}$$

用情况一的数据：8 / (8 + 1) = 8/9 ≈ 0.889。意思是 9 封真垃圾邮件里，模型找出了 8 封，漏了 1 封。

这两个指标一起看，就能明显地看出模型和"惰性模型"的区别：惰性模型的召回率是 0（一封垃圾邮件都没找出来），精确率没有定义（因为分母是 0，它一封都没判为正类）。

```python
def precision_recall(tp, fp, fn):
    p = tp / (tp + fp) if (tp + fp) > 0 else 0.0
    r = tp / (tp + fn) if (tp + fn) > 0 else 0.0
    return p, r
```

注意里面处理了分母为 0 的情况。**"没有预测出任何正类"这种情况必须处理**，否则程序会报除零错误。而这种情况在实际中很常见（比如模型太保守）。

### 精确率和召回率的取舍

这两个指标往往不能同时很高，需要在它们之间做取舍。

**提高精确率会降低召回率。** 要让模型"更有把握才判为正类"，它就会漏掉更多真正的正类。比如把判定的门槛提高，只把"非常确定"的判为垃圾邮件——精确率上去了（判为垃圾的几乎都是真的），但召回率下来了（很多垃圾邮件被放过了）。

**提高召回率会降低精确率。** 要让模型"尽量多找出正类"，它就会把更多东西判为正类，误报也就更多。比如放宽门槛，凡是有一点像垃圾邮件的都拦下来——垃圾邮件基本都拦住了（召回率高），但正常邮件也误拦了不少（精确率低）。

选哪个更重要，取决于**哪种错误代价更大**。

**误报代价大的场合，要优先精确率。** 比如垃圾邮件过滤：如果把重要邮件误判成垃圾邮件，你可能会错过一封关键的工作邮件，这个代价不小。所以宁可放过几封垃圾邮件，也不要误拦正常邮件。

**漏报代价大的场合，要优先召回率。** 比如疾病筛查：如果漏掉一个真正的患者，后果可能很严重。所以宁可多疑一些（把一些健康人也标为"需要复查"），也要尽量不漏掉患者。

这个取舍不能由算法决定，必须由人来根据具体场景决定。**这是一个价值判断，不是技术判断。**

### 综合指标：F1

如果需要用一个数字概括精确率和和召回率，可以用 F1 分数。它是两者的调和平均数：

$$F_1 = \frac{2 \times \text{精确率} \times \text{召回率}}{\text{精确率} + \text{召回率}}$$

用情况一的数据：2 乘 0.615 乘 0.889 除以 (0.615 + 0.889)，分子约 1.0935，分母约 1.504，结果约 0.727。

F1 的特点是：**它会在两者都高的时候才高**。如果一个是 1.0 另一个是 0.1，F1 只有约 0.18——它不会因为一个指标很高就给出高分。这正是我们想要的：它逼着模型在两个指标上都不能太差。

不过要注意：**F1 把精确率和召回率看成同等重要**。如果实际场景里一个明显比另一个重要，F1 就不合适，应该直接看那个重要的指标。

## 详细示例

### 示例一：计算并解读完整的一组指标

**问题**：某模型在一份 100 条测试数据上得到了这样的混淆矩阵：TP=8、FP=2、FN=4、TN=86。请算出准确率、精确率、召回率和 F1，并解读这个模型的表现。

**材料**：Python 环境；一支笔、一本练习本。

**逐步推理**：

第一步，先检查数字是否自洽。总数应该是 TP + FP + FN + TN = 8 + 2 + 4 + 86 = 100，和数据量一致。实际正类有 8 + 4 = 12 个，实际负类有 2 + 86 = 88 个。

第二步，算准确率。(TP + TN) / 总数 = (8 + 86) / 100 = 94/100 = 0.94。

第三步，算精确率。TP / (TP + FP) = 8 / (8 + 2) = 8/10 = 0.8。意思是模型判为"正类"的 10 条里，有 8 条是真的。

第四步，算召回率。TP / (TP + FN) = 8 / (8 + 4) = 8/12 ≈ 0.667。意思是 12 条真正的正类里，模型找出了 8 条。

第五步，算 F1。2 乘 0.8 乘 0.667 除以 (0.8 + 0.667)。分子是 2 乘 0.8 乘 0.667 等于 1.0672，分母是 1.467，结果约 0.727。

第六步，解读。准确率 94% 看起来很好，但要知道这个数据集里正类只占 12%。**如果全部判成负类，准确率也有 88%。** 所以 94% 相比 88% 只提高了 6 个百分点。

精确率 0.8 说明模型判为正类的可靠性还行：判了 10 条，8 条是对的。

召回率 0.667 说明模型漏掉了三分之一的正类：12 条里漏了 4 条。**这是这个模型最弱的地方。**

第七步，判断这个模型能不能用。这取决于漏报的代价。如果正类是"需要关注的邮件"，漏掉 4 条可以接受；如果正类是"有安全隐患的样本"，漏掉 4 条（三分之一）就太多了。

第八步，想改进方向。既然召回率是短板，可以提高 k（让判断更依赖更多邻居）或者调整判定策略，让模型更倾向于判为正类。代价是精确率会下降。这个取舍要由使用场景决定。

**结果**：准确率 0.94、精确率 0.80、召回率约 0.667、F1 约 0.727。模型的短板在召回率，漏掉了三分之一的正类。

**为什么正确**：我们先用总数验证了混淆矩阵自洽，再一步步算出四个指标，然后**把它们放在数据分布（正类占 12%）的背景下来解读**。如果不看数据分布，94% 这个数字会让人严重高估模型的能力。

**一个边界情况**：如果模型把所有的都判成正类呢？那 TP = 12（全部真正的正类都被找出来了），FP = 88，FN = 0，TN = 0。准确率是 (12 + 0) / 100 = 0.12（很低），精确率是 12 / (12 + 88) = 0.12（很低），召回率是 12 / (12 + 0) = 1.0（满分）。**召回率满分但精确率极低**——这个模型把所有东西都当成正类，虽然一个没漏，但也全是误报。这个例子说明：**不能只看一个指标**，任何单一指标都可以通过极端策略刷到很高。

### 示例二：根据任务目标选择指标

**问题**：下面三个任务，各自应该优先关注哪个指标？请说明理由。

```text
任务一：垃圾邮件过滤。判错的后果是重要邮件被误拦，或者垃圾邮件进入收件箱。
任务二：疾病初筛。判错的后果是患者被漏掉（耽误治疗），或者健康人被要求做进一步检查。
任务三：校园人脸门禁。判错的后果是陌生人被放进来，或者本校学生被挡在门外。
```

**材料**：上面的三个任务；一支笔、一本练习本。

**逐步推理**：

第一步，分析任务一。两种错误的代价对比：误拦一封重要邮件——你可能会错过重要信息，但通常对方会再联系你，或者你能从垃圾箱里找回来；放过一封垃圾邮件——你看到一封广告，删掉就好，代价很小。所以**误报的代价大于漏报**。应该优先精确率。

第二步，分析任务二。两种错误的代价对比：漏掉一个患者——可能耽误治疗，后果严重；把健康人标为"需要复查"——他多做一次检查，有时间和心理成本，但通常不会造成健康损害。所以**漏报的代价远大于误报**。应该优先召回率。

第三步，分析任务三。这个要仔细想。放进一个陌生人的后果可能有安全问题；挡住一个本校学生的后果是学生进不去，需要找老师处理。一般来说安全问题的后果更严重，所以**漏报（让该拦的没拦住）代价更大**，应该优先召回率。

第四步，但任务三还要多想一层。人脸门禁如果召回率定得太高（尽量拦住所有可疑的人），会导致很多本校学生被误拦，每天都不方便，最后可能有人干脆把门开着——那样反而更不安全。所以实际的做法通常是：**用召回率优先的模型做初筛，再加一个备用验证方式（比如刷卡）**。这样既不会漏掉可疑的人，也不会把学生挡在门外太久。

第五步，总结选择的依据。判断的框架是问三个问题：

1. 两种错误各自的后果是什么？
2. 哪种后果更严重、更难挽回？
3. 有没有办法兼顾（比如加一道人工确认）？

**结果**：任务一优先精确率（误报代价大）；任务二优先召回率（漏报代价大）；任务三优先召回率，但要配合备用验证方式避免误拦带来的不便。

**为什么正确**：我们没有抽象地讨论"哪个指标更好"，而是逐个分析两种错误的**具体后果**，再根据"哪种后果更难挽回"来决定。这个方法把技术指标的选择变成了对实际影响的分析，这是正确的做法。

**一个边界情况**：如果两种错误的代价差不多呢？比如一个任务里，误报和漏报的后果都是"要人工处理一次"，成本相当。这种情况下可以用 F1 分数，因为它把两者看作同等重要。或者也可以定义一个"总代价"——把误报数乘以误报的代价、漏报数乘以漏报的代价，加起来比较。**当后果可以量化时，直接用代价来比较比用指标更直接。**

## 动手实践

**目标**：用混淆矩阵和多个指标评估一个分类模型，并根据任务目标做判断。

**材料**：一台能运行 Python 的电脑；一支笔、一本练习本。

**步骤**：

1. 用上一章的模型和数据（或者重新编一份）。数据要有两类标签，其中一类明显比另一类少（比如 8:2）。**故意造成类别不平衡，这样才能看到指标之间的差别。**
2. 把数据划分成训练集和测试集。
3. 训练模型并在测试集上做预测。
4. 手工数出混淆矩阵的四个数字。数的时候要小心：**先确定哪一个类是"正类"，并写下来。**
5. 写程序自动算出混淆矩阵，和你的手工结果对照。
6. 算出准确率、精确率、召回率、F1 四个指标。
7. 算一下"惰性模型"的准确率——也就是假设全部判成多数类，准确率会是多少。把它和你的模型的准确率比较。
8. 现在调整模型，让它更倾向于判为正类（比如减小 k，或者降低判定门槛）。重新测试，算出四个指标。
9. 做一张对比表，把调整前后的四个指标并排放在一起。看看哪个指标变高了、哪个变低了。
10. 再做一次调整，让它更倾向于判为负类。同样算出四个指标。
11. 写一段结论：在你的数据上，牺牲精确率能不能换来召回率？换来的幅度有多大？如果要在这个任务上选一个方案，你会选哪个，为什么？

**完成判据**：数据的类别明显不平衡；正类的定义写清楚了；混淆矩阵手工和程序的结果一致，且四个数字之和等于测试集大小；四个指标都算对了；算出了惰性模型的准确率并做了比较；三次调整（原始、倾向正类、倾向负类）的指标都做成了对比表；结论说明了取舍关系，并给出有依据的选择。

**排查方法**：

- 如果准确率很高但召回率很低，说明模型基本只在判多数类。这时准确率这个指标没有参考价值。
- 如果精确率分母为 0 导致报错，说明模型一个正类都没预测出来。加上分母为 0 的保护，返回 0，并且在报告里说明这种情况。
- 如果四个数字加起来不等于测试集大小，检查分类的四种情况有没有漏掉或重复计算。
- 如果分不清 FP 和 FN 哪个是误报哪个是漏报，记住这个名字的含义：FP 里的 F 表示"假"（判错了），P 表示"判成了正类"——所以是"把负类误判成正类"，也就是误报。
- 如果调整模型后所有指标都变差了，检查是不是改动引入了别的问题（比如 k 变得太大导致欠拟合）。

## 常见误区

### 误区一："准确率高就说明模型好"

**错误说法**：准确率 95%，这个模型很可靠。

**为什么错**：在类别不平衡的数据上，准确率会被多数类主导。如果 100 条数据里 95 条都是 A 类，那么"全部判成 A"就能达到 95% 的准确率，而这个模型完全没用。所以**单看准确率无法判断模型是不是真的学到了东西**。

**正确理解**：看到准确率，先问两个问题：数据里两类各占多少？如果全判成多数类，准确率是多少？把自己的模型和这个"底线"比较，才能看出它有没有真的贡献。

### 误区二："精确率和召回率都要越高越好，越多越好"

**错误说法**：两个指标都往高了调就行。

**为什么错**：它们通常是此消彼长的关系。要提高精确率（让判为正类的更可靠），就得提高门槛，结果漏掉更多正类，召回率下降。要提高召回率，就得放宽门槛，结果误报更多，精确率下降。**想同时大幅提高两者，只能靠改进模型本身（更好的特征、更多的数据），而不是靠调整判定策略。**

**正确理解**：承认取舍的存在，然后根据"哪种错误代价更大"来选择偏向哪一边。这个决定应该由使用场景决定，而且要明确说出来。

### 误区三："F1 分数高就万事大吉"

**错误说法**：F1 同时考虑了精确率和召回率，看它就够了。

**为什么错**：F1 隐含了一个假设——**精确率和召回率同等重要**。但在很多实际任务里，它们的重要性差得很远。比如疾病筛查里漏报的代价远大于误报，这时用 F1 会低估"召回率高"这个优点的价值。反过来，垃圾邮件过滤里误报代价大，用 F1 也会误导。

**正确理解**：F1 适合"两者确实同等重要"或者"不清楚哪个更重要、想要一个总体印象"的场合。当你知道哪个更重要时，应该直接看那个指标，并说明另一个作为参考。

## 本章小结

- 混淆矩阵把预测分成四类：TP（判对的正类）、FP（误报）、FN（漏报）、TN（判对的负类）；先要定义清楚哪个是正类。
- 准确率在类别不平衡时会误导；应该同时算出"全部判成多数类"的准确率作为对照底线。
- 精确率是"判为正类的里面有多少是真的"，召回率是"真正的正类里找出了多少"；两者通常此消彼长。
- 优先精确率还是召回率，取决于哪一种错误代价更大；这是价值判断，要明确说出来。
- F1 是两者的调和平均数，适合两者同等重要的场合；知道哪个更重要时应该直接看那个指标。
