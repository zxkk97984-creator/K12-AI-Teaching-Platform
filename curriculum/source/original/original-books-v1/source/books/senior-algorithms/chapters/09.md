# 图与图的遍历

## 学习目标

- 能用邻接表表示一张图，并说明它与邻接矩阵各自的代价。
- 能写出广度优先和深度优先两种遍历，说明它们的差别以及各自适合回答什么问题。
- 能识别“无权图上的最短路径”和“有依赖关系的任务排序”这两类问题，并选用正确的算法。
- 能判断一张无向图是否有环、一张有向图是否存在拓扑序，并说明判据。

## 开始之前

先修要求：理解第八章的树（树是图的一种特例）、会用 `collections.deque`、会用集合记录“已经访问过”的状态。

热身问题：一个校园有 6 栋楼，楼与楼之间有道路相连。你能从 1 号楼走到 6 号楼吗？要走几条路？如果道路是双向的，能不能不重复地走完所有楼再回来？这三个问题的答案分别对应本章要讲的三种算法。

材料：Python 3.12 环境。

## 情景导入

校园导览小程序需要回答几个问题：从图书馆到食堂最少经过几栋楼？有没有哪栋楼从校门出发完全走不到？选修课的先后关系里有没有循环依赖？

负责的同学一开始想用树来做，因为第八章刚学过树，用起来顺手。但他很快发现不行：树里每个节点只有一个父节点，而现实中的建筑之间是互相连通的——从 A 能到 B，从 B 也能到 A，还可以绕着走一圈回到起点。这种“谁都能连谁”的结构就是图。

换成图之后，第一个问题（最少经过几栋楼）用广度优先搜索解决了；第二个问题（走不到的楼）用一次遍历就能找出；第三个问题（循环依赖）用拓扑排序解决。三个问题的算法各不相同，但都建立在同一件事上：**系统地访问图中的每个节点，且不重复访问**。

## 知识讲解

### 图怎么表示：邻接表与邻接矩阵

图由节点（也叫顶点）和连接节点的边组成。边可以有方向（有向图）或没有方向（无向图），也可以带权（比如道路长度）。

最常用的两种存储方式：

**邻接表**：对每个节点，记录一个列表，存它直接相连的所有节点。用字典表示就是“键是节点，值是一个列表”。

```python
g = {"A": ["B", "C"], "B": ["A", "D"], "C": ["A", "D"], "D": ["B", "C", "E"], "E": ["D"]}
```

**邻接矩阵**：用一个二维表，第 $i$ 行第 $j$ 列记录节点 $i$ 和 $j$ 之间有没有边。空间是 $O(V^2)$，$V$ 是节点数。

两者的取舍很清楚：

| 关注点 | 邻接表 | 邻接矩阵 |
| --- | --- | --- |
| 空间 | $O(V + E)$ | $O(V^2)$ |
| 判断两点是否直接相连 | $O(\deg)$，要扫该点的列表 | $O(1)$，直接查表 |
| 遍历某点的所有邻居 | $O(\deg)$ | $O(V)$，要扫一整行 |
| 适合的场景 | 稀疏图（边远少于 $V^2$） | 稠密图、需要频繁判断任意两点是否相连 |

现实中的图大多是稀疏的：一个校园里几十栋楼，有多少条道路？远少于 $V^2$ 条。所以本书一律用邻接表。$E$ 表示边的数量，无向图里每条边会在两个节点的列表里各出现一次，所以列表总长度是 $2E$。

### 广度优先搜索：一层一层往外扩

广度优先搜索（BFS）的思路是：先把起点的所有邻居访问完，再访问邻居的邻居，像水波一样一层层扩散。实现的关键是用**队列**：谁先被放进队列，谁就先被处理，从而保证按层的顺序访问。

```python
from collections import deque

def bfs(graph, start):
    dist = {start: 0}
    q = deque([start])
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in graph.get(u, []):
            if v not in dist:
                dist[v] = dist[u] + 1
                q.append(v)
    return order, dist
```

**为什么 BFS 能求出无权图的最短路径。** 关键在于“第一次遇到某个节点时，走的步数一定是最少的”。因为 BFS 按层推进，所有距离为 $k$ 的节点一定在距离为 $k-1$ 的节点全部处理完之后才被访问。如果一个节点能被更短的路径到达，那条路径上的中间节点会更早进入队列，从而更早发现它。这不是巧合，而是队列的先进先出顺序带来的保证。

用一张 5 个节点的图测试：

```python
g = {"A": ["B", "C"], "B": ["A", "D"], "C": ["A", "D"], "D": ["B", "C", "E"], "E": ["D"]}
order, dist = bfs(g, "A")
print(order)
print(dist)
```

**预期输出。**

```text
['A', 'B', 'C', 'D', 'E']
{'A': 0, 'B': 1, 'C': 1, 'D': 2, 'E': 3}
```

**核对。** A 是起点，距离 0；B 和 C 都与 A 直接相连，距离 1；D 通过 B 或 C 到达，距离 2；E 只能通过 D 到达，距离 3。访问顺序严格按距离从小到大排列，这正是广度优先的特征。

### 深度优先搜索：一条路走到底

深度优先搜索（DFS）顺着一条路一直往前走，走不通了再退回上一个岔路口。它有两种实现方式：递归，或者用**栈**显式实现。

```python
def dfs_iter(graph, start):
    seen = set()
    order = []
    stack = [start]
    while stack:
        u = stack.pop()
        if u in seen:
            continue
        seen.add(u)
        order.append(u)
        for v in reversed(graph.get(u, [])):
            if v not in seen:
                stack.append(v)
    return order
```

**注意 `reversed` 这个细节。** 栈是后进先出，把邻居按相反顺序压栈，弹出时就会按原来的顺序访问。如果去掉 `reversed`，输出顺序会反过来。两种都是合法的 DFS，但顺序固定下来才能在测试时对照结果。

```python
print(dfs_iter(g, "A"))
```

**预期输出。**

```text
['A', 'B', 'D', 'C', 'E']
```

**和 BFS 的差别。** BFS 的访问顺序是 A、B、C、D、E，DFS 是 A、B、D、C、E。DFS 沿着 A→B→D 一路深入，走到 D 之后才发现 C 还没访问（C 是 A 的邻居，但 A 处理时压栈的顺序让 B 先出），于是从 D 访问 C，再访问 E。

**两者的适用场合不同。** 需要“最短步数”时用 BFS；需要“能不能到达”“有没有环”“按依赖顺序输出”时用 DFS 就够了，而且 DFS 用递归写往往更简洁。同一张图，两种遍历都能访问到所有节点，代价都是 $O(V+E)$——因为每个节点最多被处理一次，每条边最多被检查一次。

### 有向图、入度与拓扑排序

有向图的边有方向：从 A 指向 B，表示“A 必须在 B 之前完成”。课程的先修关系就是典型的有向图。

**入度**是指向某个节点的边的数量。入度为 0 的节点表示“没有任何前置要求”，可以立刻开始。拓扑排序的算法就建立在这上面：

1. 把所有入度为 0 的节点放进一个队列。
2. 从队列取出一个节点，输出它，然后“删除”它出发的所有边——也就是把它所有邻居的入度减 1。
3. 如果某个邻居的入度因此变成了 0，把它加入队列。
4. 重复，直到队列为空。

```python
def topo(graph):
    indeg = {u: 0 for u in graph}
    for u in graph:
        for v in graph[u]:
            indeg[v] = indeg.get(v, 0) + 1
    q = deque([u for u in graph if indeg[u] == 0])
    out = []
    while q:
        u = q.popleft()
        out.append(u)
        for v in graph[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    return out if len(out) == len(indeg) else None
```

```python
learn = {"数学": ["算法"], "编程": ["算法"], "算法": ["机器学习"], "统计": ["机器学习"], "机器学习": []}
print(topo(learn))
print(topo({"A": ["B"], "B": ["C"], "C": ["A"]}))
```

**预期输出。**

```text
['数学', '编程', '统计', '算法', '机器学习']
None
```

**两条结论。** 第一，拓扑序给出了一个合法的学习顺序：先学数学、编程、统计，再学算法，最后学机器学习。注意拓扑序**不唯一**——数学、编程、统计三者的先后可以任意调换，只要满足依赖关系即可。第二，第二个含环的输入返回 `None`，表示**不存在拓扑序**。判据是：如果输出的节点数少于总节点数，说明剩下的节点互相依赖形成了环，无法排出一个满足所有依赖的顺序。

这也是“判断有向图有没有环”的标准方法：能不能完成拓扑排序，等价于有没有环。

### 无向图找环：不能走回头路

无向图判环需要额外注意一件事：**不能沿着来时的边走回去**。如果从 A 走到 B，再看到 A，那不是环，只是原路返回。

```python
def has_cycle_undirected(graph):
    seen = set()

    def dfs(u, parent):
        seen.add(u)
        for v in graph.get(u, []):
            if v not in seen:
                if dfs(v, u):
                    return True
            elif v != parent:
                return True
        return False

    for node in graph:
        if node not in seen:
            if dfs(node, None):
                return True
    return False
```

```python
print(has_cycle_undirected(g))
print(has_cycle_undirected({"A": ["B", "C"], "B": ["A"], "C": ["A"]}))
```

**预期输出。**

```text
True
False
```

**核对。** 第一张图里 A→B→D→C→A 构成一个环，返回 `True`。第二张图是一棵树（三个节点两条边），返回 `False`——这也说明**树是无环连通图的特例**，两者用同一套算法就能区分。

**为什么外层要遍历所有节点。** 因为图可能是**不连通**的：从某一个起点出发可能访问不到全部节点。所以外层循环要检查每个节点是否被访问过，没访问过就从它开始新一轮 DFS。这个外层循环同时解决了“连通分量计数”的问题。比如图 `{"A":["B"],"B":["A"],"C":["D"],"D":["C"],"E":[]}` 有三个连通分量：`['A','B']`、`['C','D']` 和单独的 `['E']`。

## 详细示例

### 示例一：用 BFS 求无权图最短路径

任务：在校园图上求出从图书馆到食堂的最少经过楼数，并给出具体路径。

**推理过程。** BFS 能算出每个节点的距离，但不会直接给出路径。要还原路径，需要在访问时记录“每个节点是从哪个节点走过来的”，也就是记录父节点。访问完成后从终点沿着父节点往回走，就能得到完整路径。

```python
from collections import deque

def shortest_path(graph, start, goal):
    parent = {start: None}
    q = deque([start])
    while q:
        u = q.popleft()
        if u == goal:
            break
        for v in graph.get(u, []):
            if v not in parent:
                parent[v] = u
                q.append(v)
    if goal not in parent:
        return None
    path = []
    cur = goal
    while cur is not None:
        path.append(cur)
        cur = parent[cur]
    return path[::-1]

campus = {
    "图书馆": ["教学楼", "食堂"],
    "教学楼": ["图书馆", "实验楼", "食堂"],
    "食堂": ["图书馆", "教学楼", "宿舍"],
    "实验楼": ["教学楼", "宿舍"],
    "宿舍": ["食堂", "实验楼"],
}
print(shortest_path(campus, "图书馆", "实验楼"))
print(shortest_path(campus, "图书馆", "宿舍"))
print(shortest_path(campus, "宿舍", "图书馆"))
```

**预期输出。**

```text
['图书馆', '教学楼', '实验楼']
['图书馆', '食堂', '宿舍']
['宿舍', '食堂', '图书馆']
```

**核对。** 图书馆到实验楼：走图书馆→教学楼→实验楼，两条边；也可以走图书馆→食堂→宿舍→实验楼，三条边，所以最短是 2 条边（经过 3 栋楼）。图书馆到宿舍：走食堂只要 2 条边，另一条路走实验楼要 3 条边。反向的宿舍到图书馆同样给出 2 条边，路径正好相反，说明无向图的对称性被正确体现。

**为什么正确。** 从终点沿父节点回溯得到的路径长度为 $dist(goal)$，而 $dist(goal)$ 是 BFS 保证的最短距离。回溯本身代价是 $O(\text{路径长度})$，远比再做一次搜索便宜。

**边界情况。** 起点等于终点时，路径是只含起点的一个列表，长度为 1，`dist` 为 0。终点不可达时返回 `None`，而不是返回一个空列表——空列表可能与“起点等于终点但列表为空”混淆，用 `None` 表示“不可达”更明确。

### 示例二：拓扑排序揭示循环依赖

任务：某选课系统记录了课程的先修关系，需要给出一个可行的修读顺序，并检查是否存在循环依赖。

用示例中的课程图，算法输出的第一个拓扑序是 `['数学', '编程', '统计', '算法', '机器学习']`。核对依赖关系：数学在算法之前（满足），编程在算法之前（满足），统计在机器学习之前（满足），算法在机器学习之前（满足）。所有依赖都被满足。

现在假设教务处误把“机器学习”设为“算法”的先修课，形成 算法→机器学习→算法 的环。这时 `topo` 会返回 `None`，并且输出的节点数会少于总节点数。**这就是排查循环依赖的方法**：如果返回 `None`，把原始图中所有还没被输出的节点找出来，它们就是构成环的那一批——因为只有环上的节点会互相把对方的入度撑着降不到 0。

```python
broken = {"数学": ["算法"], "编程": ["算法"], "算法": ["机器学习"],
          "统计": ["机器学习"], "机器学习": ["算法"]}
print(topo(broken))
```

**预期输出。**

```text
None
```

**注意拓扑序不唯一这一点。** 同一个图用不同的实现（比如把队列换成栈）会得到不同的合法顺序。所以测试时**不能断言输出等于某个固定的列表**，而应当断言“输出包含所有节点”且“每条边都满足先序关系”。这是一个很容易写错的测试断言。

**边界情况。** 没有边（所有课程的依赖列表都为空）时，任何顺序都是合法的拓扑序，程序会把所有节点输出。有自环（某课程把自身列为先修课）时同样返回 `None`，这是应该报告给使用者的错误，而不是一个合法的顺序。

### 示例三：连通分量与不可达节点

任务：找出一张图中从某个起点出发到不了的所有节点。

```python
def reachable_from(graph, start):
    return set(bfs(graph, start)[1].keys())

g2 = {"A": ["B"], "B": ["A"], "C": ["D"], "D": ["C"], "E": []}
print(sorted(reachable_from(g2, "A")))
print(sorted(set(g2) - reachable_from(g2, "A")))
```

**预期输出。**

```text
['A', 'B']
['C', 'D', 'E']
```

**核对。** 从 A 出发只能到达 A 和 B（它们互相连通）；C、D 构成另一个连通分量，E 完全孤立。用“全部节点集合减去可达集合”就得到了不可达节点列表。

**为什么这个结果值得注意。** 在做校园导览这类应用时，“不可达的楼”往往意味着地图数据本身有误（漏了一条路），而不是真的走不到。程序能发现这个信号，但需要人来判断是数据错误还是真实情况。**算法给出的是计算结果，不是结论**——这句话在工程中很重要。

**边界情况。** 起点不在图中时，`graph.get(start, [])` 返回空列表，`dist` 只有一个键（起点本身），可达集合就是 `{start}`。此时“不可达节点”会包含所有真实节点，看起来像是图坏了，但实际上是调用方传错了起点。更稳妥的做法是在函数开头检查 `if start not in graph: raise ValueError(...)`。

**完成判据**：图的双向性检查通过；BFS 和 DFS 的实际输出与手工核对一致；连通分量在加孤立点前后有可比较的真实输出；第 6 步的回答用到了“可达集合”这个说法，而不是“大概走不到”。

**排查方法**：如果 BFS 或 DFS 卡住不结束，依次检查三点。第一，无向图的边是不是只写了一个方向——如果 A 的邻居里有 B 而 B 的邻居里没有 A，那其实是有向图，但算法仍能跑完，只是结果不符合预期。第二，BFS 里的 `if v not in dist` 判断是否漏了，漏掉会导致同一个节点被反复入队，队列永不空。第三，DFS 用栈实现时，有没有在**弹出**时判断 `if u in seen`，如果没有这个判断，同一个节点可能被重复压栈并重复展开邻居。第四，如果图很大且规模超出预期，检查是不是把边的双向记录写了两遍导致退化。

## 常见误区

**误区一：“广度优先搜索能找到任意图上的最短路径。”** 反例：如果边上有权（比如道路长度不同），BFS 只能按“经过几条边”计算，找出的未必是总长度最短的那条。假设 A→B 长 10 米，A→C→B 各长 3 米和 3 米，BFS 会选 A→B 这条 1 条边的路径，但它的总长度是 10，而两条边的那条只有 6。**加权图上求最短路径需要用其他算法**（如 Dijkstra 算法），本章只讨论无权图。

**误区二：“深度优先搜索一定能找到环。”** 反例：无向图判环时必须区分“从子节点看到父节点”这种情况，否则每一棵树都会被误判为有环。上面代码里 `elif v != parent` 这个判断就是为此存在的。另一个常见的错误是**在有向图里照搬无向图的做法**：有向图中从 u 到 v 有边、从 v 到 u 也有边，这不构成环（那只是两条方向相反的单向边）。有向图判环的正确做法是拓扑排序，或者用“三色标记”（未访问、正在访问、已完成）来判断是否回到了“正在访问”的节点。

**误区三：“拓扑排序的结果是唯一的。”** 反例：三节课互不为先修，任何排列都合法。这一点在写测试时尤其致命——把输出和某个固定列表做相等断言，测试会随机失败。正确的断言是检查两个性质：输出包含全部节点；对每条边 (u, v)，u 在输出中的位置早于 v。

## 本章小结

- 图用邻接表存储时空间是 $O(V+E)$，适合稀疏图；邻接矩阵用 $O(V^2)$ 换来 $O(1)$ 的“判断两点是否相连”。
- 广度优先搜索用队列按层推进，第一次遇到节点时的距离就是最短距离，因此能在无权图上求最短路径；路径要靠记录父节点来还原。
- 深度优先搜索顺着一条路深入，可以用递归或显式栈实现；它适合判断可达性、找环、按依赖输出，但不能保证最短路径。
- 拓扑排序通过反复取出入度为 0 的节点来完成；如果输出节点数少于总数，就说明存在环。拓扑序不唯一，测试时要断言性质而不是断言具体序列。
- 下一章会进入设计策略：面对一个看似复杂的问题，怎样判断它能不能用“每步都选当前最好”的办法解决。
